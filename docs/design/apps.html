Mirror Core Apps

v0.1 · review sample

Reference designs for the three core apps — Files, Terminal, and Settings — each shown in its four required states: navigation (populated and fully interactive), loading, empty, and failure. Switch states with the segmented control, or reach them organically: the Downloads folder is genuinely empty, the fixture disk genuinely fails, and fault in the terminal genuinely errors.

01 — Files

File manager

Toolbar with back/forward history, breadcrumb path bar, filter field, and list/grid toggle. Sidebar for places and devices. The list shows name, size, and modified time; folders drill in, the status bar counts items and free space.

Files— /home

Try it: double-click folders to navigate, use the breadcrumbs and back button to return. Downloads is empty, block-test.img fails to read, filtering to no match shows the search-empty state.

02 — Terminal

Console

A live prompt over Mirror's diagnostic surface: colored output classes, an inline busy indicator for long commands, errors that explain and recover. History with ↑, clear wipes the scrollback, and every line is honest about what the system can actually do.

Terminal— console

Try it: help lists commands; blocks reads the fixture (watch the busy state); fault simulates a contained failure; an unknown command shows the recovery path.

03 — Settings

System settings

Section navigation on the left, search that genuinely filters, and controls that map to the design system. Agent access stays locked behind a broker grant — requesting one demonstrates the inline failure banner and its retry.

Settings— appearance

Try it: search zzz for the empty state, open Agent access and request a grant for the failure state, and flip Dark theme — it re-themes this whole page.
