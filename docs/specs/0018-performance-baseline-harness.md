## Goal
A repeatable method, with tooling, that measures the four v1 performance gates on Ubuntu, Windows 11 and Mirror in one reference VMware VM, with the same host-side instruments for all three, in the monitor mode the host runs (D13). When done, the baseline VMs are documented and rebuildable, `scripts/perf.ps1` and a native host tool (`tools/perf-probe`) run the measurements mostly unattended, and `docs/perf/baselines.md` holds the first Ubuntu and Windows numbers for all four gates, the input for O3. Mirror rows use the same method once 0010, 0013, 0015a, 0017c and 0019 land, with debug and release rows labeled (D11).

## Non-goals
- Setting target numbers (O3 is answered afterwards, in a ledger update and 0199).
- Emitting Mirror's perf markers, parsing `mirror.perf=`, and the `shell_ready` source: 0019 implements the kernel side of D9 against the marker contract below. Device and link telemetry (ledger C3) is also 0019's.
- Optimizing Mirror; throughput gates (disk, network, tokens/s) or app launch time.
- Gate numbers from QEMU (QEMU runs a non-gating check lane only). VirtualBox is not a target (ledger G3a, amended 2026-10-09).
- True photon latency; scripted OS installation (a manual recipe is used); CI (P3).

## Interfaces
### Gate methods
Host times use QueryPerformanceCounter (QPC). Every result reports N, median, p95, min and max.

1. **Boot (D5).** `perf-base` is a powered-off snapshot taken after a full shutdown (Windows: `shutdown /s /t 0`, so Fast Startup does not apply), after at least 3 settling boots and after the VM is encrypted (vm-setup.md). Each boot starts from `vmrun revertToSnapshot <vmx> perf-base`; 1 discarded boot, then 10 measured. `perf-probe boot` polls VNC from power-on. Diagnostics: Mirror, the host arrival time of the first serial line (kernel/src/main.rs:53) and `MIRROR_PERF_T`; Ubuntu, `systemd-analyze` and `critical-chain`; Windows, Diagnostics-Performance event 100 (BootTime, MainPathBootTime, BootPostBootTime).
2. **Idle memory (D6).** No input after the boot end event; a sample every 10 s from minute 10 to 12; a boot's value is its median; 5 boots. Mirror: `MIRROR_PERF_MEM`. Ubuntu: a shell loop over /proc/meminfo (also MemTotal, Committed_AS). Windows: `typeperf` (Available Bytes, Committed Bytes) and `Win32_OperatingSystem.TotalVisibleMemorySize`. Guest samplers start with `vmrun runProgramInGuest`, results return with `CopyFileFromGuestToHost`, and their own footprint is recorded.
3. **Input latency (D7).** Target: a focused plain-text document in the default editor (Notepad, GNOME Text Editor, Mirror's text app at the time; 0085's editor once it lands, ledger G10). Setup, untimed, opens and focuses it; on Mirror it does so with absolute RFB pointer events at positions recorded by `perf-probe snapshot` (D12). After the focusing click, perf-probe parks the pointer outside every probe rectangle. On Mirror, `perf-probe input` and `snapshot` require `MIRROR_VMMOUSE_READY mode=absolute` (0017c) in the serial log before the first pointer event and stop with an error otherwise, because VMware's VNC server cannot tell an RFB client the guest's pointer mode. perf-probe keeps one incremental update request outstanding.
   - Keypress: from writing the RFB KeyEvent(down) to the first update in which at least K pixels (default 16) of a probe rectangle at the caret differ from the pre-input frame; K and the rectangle go in the CSV header. perf-probe sends KeyEvent(up) as soon as the changed frame arrives, or after a 400 ms timeout, so VMware's 500 ms remote typematic delay (`mks.RemoteDisplay.defaultTypematicDelayUS`) never fires; a sample that times out is recorded as a timeout, and the row gives the count. `mks.disableRemoteClientTypematic` is not set, since it would add a VMX difference. Keys alternate `a` and BackSpace with random 250-750 ms gaps; 20 warm-up and 200 measured keys per session; 3 sessions.
   - Click: an untimed absolute RFB PointerEvent with no button moves the pointer to the launcher (Start button, GNOME Activities, Mirror's launcher) at the position recorded by `perf-probe snapshot`; every OS gets the same single move, with no homing step (D12). Timing runs from button-down to the first changed frame in the launcher's response rectangle. On Ubuntu and Windows an untimed Escape then closes what opened. On Mirror the click launches an app, the response rectangle is the opened app window's area, and an untimed absolute click on that window's close control closes it instead of Escape, because Escape exits Mirror's shell (`userspace/desktop/src/shell.rs:379`) and the shell has only two app slots (`crates/window-protocol/src/lib.rs:19`). 100 clicks per session; 3 sessions.
4. **Agent action (D8).** 20 warm-up and 200 measured iterations per session (pixel path: 50); 3 sessions; the text alternates between two fixed strings.
   - Mirror: the Agent API (0045) bench client that `mirror.perf=agent` starts (0019) does a typed Read then Replace, timed with `SYS_CLOCK_GET` (crates/clock-protocol/src/lib.rs:10) or its `mirror-sys` successor.
   - Windows: C# compiled in the guest by PowerShell 5.1 `Add-Type` (inbox .NET Framework 4.8.x): `TextPattern.DocumentRange.GetText(-1)`, then `ValuePattern.SetValue`, timed with `Stopwatch`.
   - Ubuntu: Python with pyatspi: `Text.getText(0, -1)`, then `EditableText.setTextContents`, timed with `time.perf_counter_ns`.
   - Pixel path, from the host: read = receive one full frame; act = the app's select-all shortcut, then 32 key presses; confirm = the first frame whose document rectangle matches the expected-text template captured at setup.

### Mirror marker contract (D9; emitted by 0019)
The harness reads these serial lines. `ns` is HPET time since `clock::init`, read with `clock::snapshot` (kernel/src/clock.rs:295-316, BSP with IF clear only), or `none` after `MIRROR_CLOCK_SKIPPED`.
- `MIRROR_PERF_T event=<display|input|userspace|shell_ready> ns=`, always on, each once, in order: framebuffer ready (today kernel/src/main.rs:164); PS/2 init done (kernel/src/main.rs:257-283); first user process started (the shell, after 0010-D3); the shell's first complete frame, from a source 0019 defines that survives 0010 (today the only signal is a console string, userspace/desktop/src/shell.rs:867-868, matched at kernel/src/userspace.rs:2657-2667, which 0010 removes from default builds).
- `mirror.perf=1`: `MIRROR_PERF_MEM ns= available_kib= pool_kib=` at enable and every 10 s; `MIRROR_PERF_INPUT seq= irq_ns= present_ns=` (keyboard IRQ to first present; may wait for 0084).
- `mirror.perf=flip`: before userspace, 100 alternating full-screen fills 500 ms apart, each followed by `MIRROR_PERF_FLIP seq= ns=`. `mirror.perf=agent`: starts the bench client (after 0045), which prints numeric `MIRROR_PERF_AGENT seq= ns=` only.

### Files and tools
- `tools/perf-probe/`: its own `[workspace]`, leaving the root members list (Cargo.toml:2) alone. `.cargo/config.toml:1-2` defaults repo cargo runs to x86_64-unknown-none, so it uses `--target x86_64-pc-windows-msvc` like the host tests (scripts/test.ps1:69). Subcommands: `boot`, `input`, `pixel-agent`, `calibrate` (VNC update cadence; Mirror serial-to-frame delay under `mirror.perf=flip`), `snapshot` (reference frame, mask, and the D12 pointer targets in framebuffer coordinates: the launcher and document positions, and on Mirror the opened app window's area and close control), `serial` (connect as the client to the VMware named-pipe serial port right after `vmrun start`, read continuously, and stamp each line with QPC), `summarize` (CSV to baselines.md rows). Every subcommand that connects over VNC writes the RFB ServerInit framebuffer size into its CSV header. `input`, `snapshot`, `calibrate` and `pixel-agent`, which connect to a booted desktop, stop with an error on VMware unless it is 1920x1080 (D3). `boot` connects at power-on, while firmware and the loader still use their own modes, so it records each size it sees through the DesktopSize pseudo-encoding, which it must advertise: without it VMware 26.0.1 cannot send the mode change to the client ("Unable to send display mode change to client."; whether it then drops the client is inferred), so reconnecting is only a fallback. `boot` requires its end frame to be 1920x1080. `calibrate` also times one non-incremental Raw full-frame request at 1920x1080; reports the cadence separately for Mirror and the baselines, with 3D on and, for reference, with 3D off (toggled with `vmcli <vmx> MKS SetAccel3d` while the VM is powered off, and set back before any gate row); and copies the vmware.log `MKSFrame: Switching to <mode> compositing rate: fps=<n>` line, or its absence, into its CSV header. If Raw frames are throttled, vm-setup.md records the `RemoteDisplay.*` override used, identical on all three VMs.
- `scripts/perf.ps1 -Os mirror|ubuntu|windows -Gate boot|idle|input|agent|all [-Hypervisor vmware|qemu] [-Vmx <path>] [-Vmrun <path>]` (`-Vmx` required for VMware). It resolves `vmrun.exe` from `-Vmrun` or from the `InstallPath` value of `HKLM\SOFTWARE\VMware, Inc.\VMware Workstation` (64-bit registry view; there is no WOW6432Node key), never from PATH, runs it as `vmrun -T ws`, and passes `-vp` to `revertToSnapshot` and `start`. After `vmrun start` it fails the run if the VNC port does not accept a connection within a timeout, so a VM waiting on a question cannot hang it (the 26H1 guide says vmrun may time out on such a VM). Guest credentials and the VM encryption password come from the untracked `build/perf/guests.json`. Before it builds perf-probe, it runs 0011's `Assert-MirrorToolchain` once 0011 has landed.
- `tools/perf-guest/windows/` (typeperf sampler, UIA agent) and `tools/perf-guest/linux/` (meminfo sampler, AT-SPI agent), copied in with `vmrun CopyFileFromHostToGuest`.
- `docs/perf/vm-setup.md`: per-VM manual recipe (amended 2026-10-10 after the VMware Workstation Pro 26.0.1 check):
  - Host: record the Workstation build (26.0.1 build 25688693, from the vmware.log header) and turn off the software-update check and component download in Preferences. Power on a scratch VM once and record the vmware.log `Monitor Mode:` line; done 2026-10-10 with a throwaway diskless VM (`Monitor Mode: ULM`, no license prompt, no admin change). If a later power-on fails with the KB 76918 or "user level monitor" message, the host state has changed and D13 goes back to the owner.
  - Guests: installer name and SHA-256; D4 settings and the Windows activation state (Open question 3); `virtualHW.version` (22) and the VMware Tools or open-vm-tools version in each guest.
  - VMX hardware block (D3), with literal keys, the same in all three VMs apart from `guestOS` and D3's other exceptions: `firmware = "efi"` (a missing key means BIOS); `uefi.secureBoot.enabled = "FALSE"` (the Windows 11 wizard turns Secure Boot on, so switch it off); `sata0.present = "TRUE"` with the disk on sata0:0 and no nvme0 (do not take the wizard's controller default); `usb.present`, `ehci.present` and `usb_xhci.present` all `"FALSE"` or absent; `hpet0.present = "TRUE"`; `ethernet0.virtualDev = "e1000"`; `mks.enable3d = "TRUE"` (D4); `uuid.action = "keep"` and `msg.autoAnswer = "TRUE"`, so a headless start never stalls on a question; `answer.msg.serial.file.open = "Replace"` wherever a serial port goes to a file. Any first-listen firewall prompt is denied.

A toggle for one `calibrate` run (3D off) is applied after the revert and before `vmrun start`. Whether vmcli can edit an encrypted VM is unverified until the first such change.

### Known measurement limits
- Until 0069's SVGA II driver (ledger S1a, S1c), Mirror draws to the UEFI framebuffer, so VMware must detect its changes; the baselines' SVGA drivers send explicit updates. The user sees this, so it counts; flip calibration measures Mirror's share. VMware coalesces traced framebuffer writes over 10 ms by default (`svga.traceFBCoaleseUS = 10000`), so until 0069 Mirror's boot-end and input rows can include up to about 10 ms that the baselines do not. The key stays at its default on all three VMs (confirmed 2026-10-10: a tuned key would flatter Mirror), and flip calibration reports its effect.
- Until 0027a lifts the desktop cap, Mirror's desktop surface is a centered 1280x800 region (`kernel/src/surface.rs:38`) while the baselines draw all of 1920x1080, so Mirror draws fewer pixels per frame. Rows from that period note the cap (D3) and are not adjusted for it.
- Changes are seen at the VNC update cadence; random input phase and N ≥ 200 keep medians stable; the cadence is reported. VMware 26.0.1 composites remote frames at `RemoteDisplay.maxFPS` (67 fps when unset, capped by `mks.maxCompositingFPS`, default 100) and polls remote consoles at `mks.poll.remoteConsolePollHZ` (53 Hz); no VM sets either key, and `calibrate` shows which rate governs a nogui VM with one client.
- On the development host (Windows 11 Home 26200) the Windows hypervisor runs because VBS is on and Virtual Machine Platform (WSL2, Docker Desktop) is installed. There is no Hyper-V role, and the Windows Hypervisor Platform optional feature is off. VMware therefore runs VMs in Host VBS mode, its user-level monitor on the Windows hypervisor, as the 2026-10-10 power-on's vmware.log confirmed (`Monitor Mode: ULM`, `IOPL_Init: Hyper-V detected by CPUID`, `Syncing WHP TSCs`). In that mode guest PMCs, nested VT-x, RTM/HLE and PKU are absent, RDTSC may be trapped, and device exits cost more. Mirror's HPET, port-I/O, serial and framebuffer paths exit more often than the baselines' paravirtual paths, so these numbers may overstate Mirror's gap (inference); Mirror rows record the serial byte count up to the end frame. Rows from different monitor modes are not compared, and O3 targets name their mode (D13). Host state shifts absolute numbers, so one comparison uses one recorded host state (session preparation, vm-setup.md), with no other VM running.
- Overhead outside the timed calls (PowerShell, Python, VNC) is excluded; Python's per-call cost beside D-Bus round trips is a small known bias.

## Acceptance tests
1. Host checks in scripts/test.ps1, beside its formatting, host-test and Clippy steps, each with `--manifest-path tools/perf-probe/Cargo.toml`, as the AGENTS.md bullet lists them: `cargo fmt --check`; `cargo clippy --locked --target x86_64-pc-windows-msvc -- -D warnings`; and `cargo test --locked --target x86_64-pc-windows-msvc`, covering the RFB 3.8 handshake (security None) and Raw update parsing from recorded byte fixtures, which include a handshake recorded from VMware (server version, security list `01 01`, SecurityResult `00000000`) and a VMware DesktopSize rect, the ServerInit size check and `boot`'s handling of a size change before the end frame (D3), key and absolute pointer event encoding (D12), the masked-diff threshold, template matching, median and p95 on known vectors, and serial line stamping.
2. QEMU lane: `scripts/perf.ps1 -Os mirror -Gate boot -Hypervisor qemu` boots the current normal build 3 times and reports 3 boot times, each end frame saved under `build/perf/`, with no timeouts.
3. Probe sanity on VMware, per baseline OS, before any gate row: the VNC framebuffer is 1920x1080 (D3); `netstat -ano` shows the VNC port listening only on 127.0.0.1; with 3D on, a static desktop frame from VNC matches a guest-side screenshot outside the cursor mask; one absolute VNC move to each screen corner lands exactly (D12); on an idle desktop the input probe sees no change in 60 s; `perf-probe calibrate` reports into baselines.md the VNC update cadence with 3D on and with 3D off, the time for one Raw 1920x1080 full frame, and whether the cursor appears in Raw frames.
4. Repeatability on VMware, per baseline OS: boot coefficient of variation ≤ 10% over 10 boots; idle-memory max − min ≤ 5% of the median over 5 boots; each session median within ±10% of the pooled median for input and agent action; a rerun on another day reproduces every median within 10%.
5. docs/perf/baselines.md has Ubuntu and Windows rows for all four gates (agent action on both the accessibility and pixel paths), each with its monitor mode (D13), the environment header, and raw CSVs under docs/perf/runs/. Each host-observed boot time is at least the guest-reported diagnostic.
6. Mirror rows: once 0010, 0013, 0015a, 0017c and 0019 have landed, `scripts/perf.ps1 -Os mirror -Gate all` yields boot, idle and input rows (with flip calibration), and after 0045 the agent row, for a debug and a release image, each row labeled with its commit, profile and features (D11). The serial log shows `MIRROR_FRAMEBUFFER_READY width=1920 height=1080`, and `MIRROR_SMP_READY` with `online=4` (`kernel/src/smp.rs:251-252`), so no row is measured on one CPU behind the legacy PIC (0013-D9). The input rows place the pointer only with absolute RFB events, with no homing step (D12), and perf-probe finds `MIRROR_VMMOUSE_READY mode=absolute` in the serial log before the first pointer event.
