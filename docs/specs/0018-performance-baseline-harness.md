# 0018: Performance baseline harness

Status: confirmed (2026-10-09; D2 and D3 amended, D11-D12 added and the Mirror click method set 2026-10-09 after the gap interview and its addendum)
Depends on: Linux and Windows baselines: VMware Workstation Pro installed on the host (owner; not installed today). Mirror rows: 0010 (no init battery at boot), 0013 (VMware firmware and PCI tolerance), 0015a (disk image), 0017c (absolute pointing, D12), 0019 (perf markers); the agent row also needs 0045. Used once landed: 0011 (toolchain preflight), 0014 (QEMU device profile).
Ledger: G7, O3, M0; uses G3a, S1a, S1c, S1d, S3, S7, S7b, S10, A11a

## Goal
A repeatable method, with tooling, that measures the four v1 performance gates on Ubuntu, Windows 11 and Mirror in one reference VMware VM, with the same host-side instruments for all three. When done, the baseline VMs are documented and rebuildable, `scripts/perf.ps1` and a native host tool (`tools/perf-probe`) run the measurements mostly unattended, and `docs/perf/baselines.md` holds the first Ubuntu and Windows numbers for all four gates, the input for O3. Mirror rows use the same method once 0010, 0013, 0015a, 0017c and 0019 land, with debug and release rows labeled (D11).

## Non-goals
- Setting target numbers (O3 is answered afterwards, in a ledger update and 0199).
- Emitting Mirror's perf markers, parsing `mirror.perf=`, and the `shell_ready` source: 0019 implements the kernel side of D9 against the marker contract below. Device and link telemetry (ledger C3) is also 0019's.
- Optimizing Mirror; throughput gates (disk, network, tokens/s) or app launch time.
- Gate numbers from QEMU (QEMU runs a non-gating check lane only). VirtualBox is not a target (ledger G3a, amended 2026-10-09).
- True photon latency; scripted OS installation (a manual recipe is used); CI (P3).

## Interfaces
### Gate methods
Host times use QueryPerformanceCounter (QPC). Every result reports N, median, p95, min and max.

1. **Boot (D5).** `perf-base` is a powered-off snapshot taken after a full shutdown (Windows: `shutdown /s /t 0`, so Fast Startup does not apply), after at least 3 settling boots. Each boot starts from `vmrun revertToSnapshot <vmx> perf-base`; 1 discarded boot, then 10 measured. `perf-probe boot` polls VNC from power-on. Diagnostics: Mirror, the host arrival time of the first serial line (kernel/src/main.rs:53) and `MIRROR_PERF_T`; Ubuntu, `systemd-analyze` and `critical-chain`; Windows, Diagnostics-Performance event 100 (BootTime, MainPathBootTime, BootPostBootTime).
2. **Idle memory (D6).** No input after the boot end event; a sample every 10 s from minute 10 to 12; a boot's value is its median; 5 boots. Mirror: `MIRROR_PERF_MEM`. Ubuntu: a shell loop over /proc/meminfo (also MemTotal, Committed_AS). Windows: `typeperf` (Available Bytes, Committed Bytes) and `Win32_OperatingSystem.TotalVisibleMemorySize`. Guest samplers start with `vmrun runProgramInGuest`, results return with `CopyFileFromGuestToHost`, and their own footprint is recorded.
3. **Input latency (D7).** Target: a focused plain-text document in the default editor (Notepad, GNOME Text Editor, Mirror's text app at the time; 0085's editor once it lands, ledger G10). Setup, untimed, opens and focuses it; on Mirror it does so with absolute RFB pointer events at positions recorded by `perf-probe snapshot` (D12). perf-probe keeps one incremental update request outstanding.
   - Keypress: from writing the RFB KeyEvent(down) to the first update in which at least K pixels (default 16) of a probe rectangle at the caret differ from the pre-input frame; K and the rectangle go in the CSV header. Keys alternate `a` and BackSpace with random 250-750 ms gaps; 20 warm-up and 200 measured keys per session; 3 sessions.
   - Click: an untimed absolute RFB PointerEvent with no button moves the pointer to the launcher (Start button, GNOME Activities, Mirror's launcher) at the position recorded by `perf-probe snapshot`; every OS gets the same single move, with no homing step (D12). Timing runs from button-down to the first changed frame in the launcher's response rectangle. On Ubuntu and Windows an untimed Escape then closes what opened. On Mirror the click launches an app, the response rectangle is the opened app window's area, and an untimed absolute click on that window's close control closes it instead of Escape, because Escape exits Mirror's shell (`userspace/desktop/src/shell.rs:379`) and the shell has only two app slots (`crates/window-protocol/src/lib.rs:19`). 100 clicks per session; 3 sessions.
4. **Agent action (D8).** 20 warm-up and 200 measured iterations per session (pixel path: 50); 3 sessions; the text alternates between two fixed strings.
   - Mirror: the Agent API (0045) bench client that `mirror.perf=agent` starts (0019) does a typed Read then Replace, timed with `SYS_CLOCK_GET` (crates/clock-protocol/src/lib.rs:10) or its `mirror-sys` successor.
   - Windows: C# compiled in the guest by PowerShell 5.1 `Add-Type` (inbox .NET Framework 4.8.x): `TextPattern.DocumentRange.GetText(-1)`, then `ValuePattern.SetValue`, timed with `Stopwatch`.
   - Ubuntu: Python with pyatspi: `Text.getText(0, -1)`, then `EditableText.setTextContents`, timed with `time.perf_counter_ns`.
   - Pixel path, from the host: read = receive one full frame; act = the app's select-all shortcut, then 32 key presses; confirm = the first frame whose document rectangle matches the expected-text template captured at setup.

### Mirror marker contract (D9; emitted by 0019)
The harness reads these serial lines. `ns` is HPET time since `clock::init`, read with `clock::snapshot` (kernel/src/clock.rs:295-316, BSP with IF clear only), or `none` after `MIRROR_CLOCK_SKIPPED`.
- `MIRROR_PERF_T event=<display|input|userspace|shell_ready> ns=`, always on, each once, in order: framebuffer ready (today kernel/src/main.rs:160); PS/2 init done (kernel/src/main.rs:253-279); first user process started (the shell, after 0010-D3); the shell's first complete frame, from a source 0019 defines that survives 0010 (today the only signal is a console string, userspace/desktop/src/shell.rs:867-868, matched at kernel/src/userspace.rs:2510-2520, which 0010 removes from default builds).
- `mirror.perf=1`: `MIRROR_PERF_MEM ns= available_kib= pool_kib=` at enable and every 10 s; `MIRROR_PERF_INPUT seq= irq_ns= present_ns=` (keyboard IRQ to first present; may wait for 0084).
- `mirror.perf=flip`: before userspace, 100 alternating full-screen fills 500 ms apart, each followed by `MIRROR_PERF_FLIP seq= ns=`. `mirror.perf=agent`: starts the bench client (after 0045), which prints numeric `MIRROR_PERF_AGENT seq= ns=` only.

### Files and tools
- `tools/perf-probe/`: its own `[workspace]`, leaving the root members list (Cargo.toml:2) alone. `.cargo/config.toml:1-2` defaults repo cargo runs to x86_64-unknown-none, so it uses `--target x86_64-pc-windows-msvc` like the host tests (scripts/test.ps1:15). Subcommands: `boot`, `input`, `pixel-agent`, `calibrate` (VNC update cadence; Mirror serial-to-frame delay under `mirror.perf=flip`), `snapshot` (reference frame, mask, and the D12 pointer targets in framebuffer coordinates: the launcher and document positions, and on Mirror the opened app window's area and close control), `serial` (stamp each line from a VMware named-pipe serial port with QPC), `summarize` (CSV to baselines.md rows). Every subcommand that connects over VNC writes the RFB ServerInit framebuffer size into its CSV header. `input`, `snapshot`, `calibrate` and `pixel-agent`, which connect to a booted desktop, stop with an error on VMware unless it is 1920x1080 (D3). `boot` connects at power-on, while firmware and the loader still use their own modes, so it records each size it sees (through the DesktopSize pseudo-encoding, or by reconnecting when the size changes) and requires its end frame to be 1920x1080.
- `scripts/perf.ps1 -Os mirror|ubuntu|windows -Gate boot|idle|input|agent|all [-Hypervisor vmware|qemu] [-Vmx <path>]` (`-Vmx` required for VMware). Guest credentials and the VM encryption password come from the untracked `build/perf/guests.json`. Before it builds perf-probe, it runs 0011's `Assert-MirrorToolchain` once 0011 has landed.
- `tools/perf-guest/windows/` (typeperf sampler, UIA agent) and `tools/perf-guest/linux/` (meminfo sampler, AT-SPI agent), copied in with `vmrun CopyFileFromHostToGuest`.
- `docs/perf/vm-setup.md`: per-VM manual recipe. First step: install VMware Workstation Pro and record its build. Then: installer name and SHA-256; the VMX hardware block (D3), including the VM encryption VMware requires for a vTPM (TPM-files-only if offered; `vmrun` then takes `-vp`); the 1920x1080 display mode and how each guest is set to it (Ubuntu and Windows in their display settings; Mirror through Limine's `resolution:` option in its perf boot entry (D3, 0015a; how 0019 delivers that entry is 0019-D12)); D4 settings and the Windows activation state (Open question 3); the VNC server (`RemoteDisplay.vnc.*`, fixed port, no password, blocked for non-loopback traffic by a host firewall rule); Mirror's VM on 0015a's `mirror.vmdk` with its serial port as a named pipe; the `perf-base` snapshot.
- `docs/perf/baselines.md`: one table per gate; rows give OS and build, date, method version, N, median, p95, min, max. Mirror rows also give the commit, profile (debug or release) and Cargo features, recorded by hand until build identity exists (0067); the `MIRROR_FRAMEBUFFER_READY` width and height; and, until 0027a lifts it, a note that the desktop is capped at a centered 1280x800 region (D3). Debug rows are marked as not counting for the gates (D11). Header: host CPU, RAM, OS build, host hypervisor state, power mode, VMware build, VMX hash.
- `AGENTS.md` (P9): perf-probe is its own workspace, so `cargo fmt --all` and `cargo clippy --workspace` do not reach it. A change under `tools/perf-probe/` runs `cargo fmt --check`, `cargo clippy --locked --target x86_64-pc-windows-msvc -- -D warnings` and `cargo test --locked --target x86_64-pc-windows-msvc`, each with `--manifest-path tools/perf-probe/Cargo.toml`, before it is committed (P8). `perf.ps1` joins the one-script-at-a-time rule in the commit that adds it (P9), since it writes under `build\perf\`.
- `docs/perf/runs/<date>-<os>-<gate>.csv`: raw samples. Frames go to `build/perf/` (ignored by `/build/`, .gitignore:2).
- QEMU lane (non-gating): perf-probe against QEMU `-vnc 127.0.0.1:<n>`, ending with QMP `quit` as capture.ps1 does (scripts/capture.ps1:524-526). Devices come from 0014's `Get-MirrorDeviceArguments -Profile V1` once 0014 has landed, and the boot medium from 0015a's disk image once 0015a has landed, so perf.ps1 keeps no QEMU device list of its own. QEMU runs TCG (scripts/run.ps1:319), so the lane checks the tooling, not timings.

### Known measurement limits
- Until 0069's SVGA II driver (ledger S1a, S1c), Mirror draws to the UEFI framebuffer, so VMware must detect its changes; the baselines' SVGA drivers send explicit updates. The user sees this, so it counts; flip calibration measures Mirror's share.
- Until 0027a lifts the desktop cap, Mirror's desktop surface is a centered 1280x800 region (`kernel/src/surface.rs:36`) while the baselines draw all of 1920x1080, so Mirror draws fewer pixels per frame. Rows from that period note the cap (D3) and are not adjusted for it.
- Changes are seen at the VNC update cadence; random input phase and N ≥ 200 keep medians stable; the cadence is reported.
- This host runs Hyper-V, so VMware runs on the Windows Hypervisor Platform. Host state shifts absolute numbers, so one comparison uses one recorded host state, on AC power, with no other VM running.
- Overhead outside the timed calls (PowerShell, Python, VNC) is excluded; Python's per-call cost beside D-Bus round trips is a small known bias.

## Acceptance tests
1. Host checks in scripts/test.ps1, beside its formatting, host-test and Clippy steps, each with `--manifest-path tools/perf-probe/Cargo.toml`, as the AGENTS.md bullet lists them: `cargo fmt --check`; `cargo clippy --locked --target x86_64-pc-windows-msvc -- -D warnings`; and `cargo test --locked --target x86_64-pc-windows-msvc`, covering the RFB 3.8 handshake (security None) and Raw update parsing from recorded byte fixtures, the ServerInit size check and `boot`'s handling of a size change before the end frame (D3), key and absolute pointer event encoding (D12), the masked-diff threshold, template matching, median and p95 on known vectors, and serial line stamping.
2. QEMU lane: `scripts/perf.ps1 -Os mirror -Gate boot -Hypervisor qemu` boots the current normal build 3 times and reports 3 boot times, each end frame saved under `build/perf/`, with no timeouts.
3. Probe sanity on VMware, per baseline OS: the VNC framebuffer is 1920x1080 (D3); on an idle desktop the input probe sees no change in 60 s; `perf-probe calibrate` reports the VNC update cadence into baselines.md.
4. Repeatability on VMware, per baseline OS: boot coefficient of variation ≤ 10% over 10 boots; idle-memory max − min ≤ 5% of the median over 5 boots; each session median within ±10% of the pooled median for input and agent action; a rerun on another day reproduces every median within 10%.
5. docs/perf/baselines.md has Ubuntu and Windows rows for all four gates (agent action on both the accessibility and pixel paths), the environment header, and raw CSVs under docs/perf/runs/. Each host-observed boot time is at least the guest-reported diagnostic.
6. Mirror rows: once 0010, 0013, 0015a, 0017c and 0019 have landed, `scripts/perf.ps1 -Os mirror -Gate all` yields boot, idle and input rows (with flip calibration), and after 0045 the agent row, for a debug and a release image, each row labeled with its commit, profile and features (D11). The serial log shows `MIRROR_FRAMEBUFFER_READY width=1920 height=1080`. The input rows place the pointer only with absolute RFB events, with no homing step (D12). No manual step is needed beyond starting each run and recording the build fields.

## Open questions

1. Does the installed VMware build still offer the per-VM VNC server (`RemoteDisplay.vnc.*`), with correct frames under 3D acceleration? If not, D5, D7 and D8's pixel path need another frame source (D7's alternative, DXGI Desktop Duplication), which goes back to the owner.
2. Do Windows 11 Notepad (`ValuePattern.SetValue`) and GNOME Text Editor (GTK4 AT-SPI `EditableText`) accept accessibility writes? If not, use a minimal app on the stock text widget (WinForms TextBox, GTK3 TextView) and record it.
3. Windows activation: the owner activates the VM with a license or leaves it unactivated when building it. The method works either way (D5 masks the watermark); vm-setup.md and the baselines.md header record the state, and one comparison keeps one state.
4. Does Windows 11 have an inbox driver for VMware's `e1000` (82545EM)? If not, the owner picks Intel's driver or VMware's Windows default `e1000e`, which breaks identical hardware (D3).
