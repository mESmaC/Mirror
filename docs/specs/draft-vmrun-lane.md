Status: draft (2026-10-12). Every recommendation below is **proposed**, not approval to implement or operate a VM. Cameron chooses the alternatives separately and assigns spec numbers.
Depends on: 0010, 0011, 0013, 0015a; merged 0017b including 0017-D9's readback amendment and merged 0017c for guest cases. Host-only work can precede D11's platform investigation. Uses 0018-D10's library without resuming benchmarks. Guest restart also requires confirmed, merged 0058a.

## Goal

An opt-in check boots a packaged Mirror image headless, verifies exact console commands through VMware VNC, and checks continuity after host suspend/resume. A guest restart case joins after 0058a. Results are functional outcomes with bounded operations and preserved evidence, not performance measurements.

This remains an approval proposal until Claude remaps it. Before implementation, split it into numbered **host library/packaging** and **VMware cases** specs, retaining these decision IDs: the former can land before the VMware prerequisite investigation; the latter depends on those experiments. Keeping the shared contract here avoids premature numbering or duplicated interfaces.

## Non-goals

Other-OS downloads, setup and benchmarks remain deferred until Cameron requests them. No completion of 0018, new guest markers, guest power/clock/Tools implementation, pointer gestures or click tests, snapshots, host security changes, CI or replacement of QEMU tests. The only pointer input is the bounded setup priming move below. The runner does not create/reconfigure VMs; proposed manual provisioning is a separate owner action below. Phase 5 can add soft-power cases later. Cross-script lock enforcement and hostile-process source isolation are outside the recommended scope.

## Interfaces

### Entry, sources and implementation boundary

Proposed entry: `scripts/vmrun.ps1 -Vmx <path> -LaneRoot <path> -LockOwner <nick/task> -Case boot|suspend-resume|restart`. Recovery uses `-Recover <run-id> [-PowerOff]` instead of `-Case`, resolves VMX from the canonical LaneRoot record and rejects a conflicting supplied VMX. Package recovery is `scripts/package.ps1 -Lane -Recover <package-id> -LaneRoot <path> -LockOwner <nick/task>`; it never needs a VMX or performs power actions. New cases never adopt an unreleased lock. Optional `-Vmrun <path>` overrides discovery through the 64-bit VMware Workstation `InstallPath` registry value. Use argument arrays and hidden processes; no credentials, implicit `all`, build or repackaging.

The Rust lane owns deadlines, transitions, oracles, journals and evidence behind injectable command, clock, serial, state/listener and artifact adapters. The host spec also puts the lane-package controller in Rust; `package.ps1 -Lane [-Release] -LaneRoot <path> -LockOwner <nick/task>` is its thin entry. Thus the cargo host tests exercise production controllers with fake command runners and temporary files, without Pester or a second orchestration implementation.

Future scope: `tools/perf-probe`, `scripts/vmrun.ps1`, `scripts/package.ps1`, host checks in `scripts/test.ps1`, and matching AGENTS/P9 and team recovery-rule documentation. Correct `docs/vm-settings.md`'s creation paragraph: only bridges 4–7 are eight-function root ports; bridge 0 is separate. Add a separate lane profile, preserving the reference block. No kernel/userspace changes, `common.ps1` retrofit or other script lock edits.

### Recommended packaging and fixed VM binding

Lane packaging acquires/releases the machine lock independently of the later VM case and never changes VM staging. Resolve one clean committed tree and export it with `git archive` under `<LaneRoot>/package/<package-id>/source`, outside every checkout, with fresh output directories. Only this controller writes the scratch tree; cooperating agents never edit it. Inventory hashes before/after detect persistent changes; they do not prevent transient tampering by another process. If stronger isolation is wanted, choose D9's sealed alternative and specify sealing, unsealing and crash cleanup in the host spec.

Cargo searches ancestors and Cargo home as well as the project ([configuration hierarchy](https://doc.rust-lang.org/cargo/reference/config.html#hierarchical-structure)). Reject `.cargo/config` and `.cargo/config.toml` in every ancestor above the export through the volume root. Resolve and record the operator's existing cached `CARGO_HOME`; reject its `config` and `config.toml`, preserve the exported project's configuration, and set `CARGO_NET_OFFLINE=true` with locked resolution ([environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html)). This uses Cargo's own cache handling, not copied internal layouts; missing cached inputs fail. Clear/reject inherited source, compiler, flags and output overrides against a recorded allowlist. Verify the pinned toolchain, and copy the verified cached Limine archive into the export's private `.tools`; no shared extraction junction or download.

Build default flavor without agent-demo/perf tokens. Copy the private build's image/descriptor to the calling checkout's `build/dist`; publish `mirror.package.json` there last and atomically: schema, package-id, source commit/tree, clean status, profile/features/toolchain, committed-source inventory, capability/oracle versions and image/descriptor sizes/SHA-256. Inventory only committed source files, excluding generated `build`, `target`, `.tools` and lane artifacts. All packaging modes invalidate an old record before replacing files; only `-Lane` publishes one. Partial/mixed generations fail. The host spec requires merged main code tips `14cb7b2` (0017b) and `3c87bcb` (0017c) as ancestors of the package commit; restart also requires the later confirmed, merged 0058a capability commit. Historical pre-rebase IDs, the later checkout HEAD and staged ELF are not provenance.

Before exporting, journal the package-id, operator, original checkout, canonical scratch/output paths, controller PID/start time and child-job identity under `<LaneRoot>/packages/<package-id>`. All Git/archive/build/PowerShell/Cargo/linker/mirror-image children and descendants belong to a separate kill-on-close job, with no breakaway or inherited controlling handle. Record each directly created worker's PID/start time while it is still suspended in that job, durably before allowing execution. The controller's death ends its build tree; the adapter must demonstrate this in host tests before packaging is enabled. After verified publication, scratch cleanup and proof of no live build, persist that package's `final.json` as `finalized-valid` before release. Lane staging requires this valid LaneRoot record as well as the matching published manifest/hashes; an incomplete or recovered-invalid record cannot be bypassed by a leftover manifest.

The controller's `finally` removes only its canonically verified scratch directory, with no reparse traversal, retaining logs/manifests outside it. After a crash, the recorded operator runs package Recover from its own checkout, obtains the lease under D6 and checks the recorded controller/worker identities and job membership. No scratch cleanup or release until the old controller has exited and its job has no live descendants; missing evidence or a live process leaves the operation blocked, never delete by age. Recover never resumes a build or publishes a partial package. For an incomplete operation it records a failed/recovered verdict and invalid generation in `<LaneRoot>/packages/<package-id>/final.json`; an already durable `finalized-valid` verdict is preserved after rechecking its hashes and no-live-build proof. It removes only any remaining verified scratch tree, then releases the machine lock using the shared release procedure. If scratch deletion is denied, preserve its exact path and an `abandoned-artifacts` failure record; after proving no live build it may still release the lock, and future packages use new identities/paths. It never writes to another checkout. Use the same named-replacement rules as VM Recover. There are no ACL seals to undo.

Provisioning records one canonical VMX-to-LaneRoot binding. Preflight requires resolved `sata0:0.fileName` = `<LaneRoot>/disk/mirror.vmdk`, its adjacent extent `mirror.img`, and `serial0.fileName` = `<LaneRoot>/serial.log`. Reject LaneRoot inside any Git worktree, beneath Cameron's `C:\Users\engin\Desktop\Mirror`, or through reparse aliases. Compare canonical Windows path components, not string prefixes: `Mirror-vm` is not beneath `Mirror`. The root must match the binding; another root cannot bypass its journal. No snapshots/parent chain or extra disk. With proven off state and lock held, stage the **calling checkout's `build/dist` image/descriptor and `mirror.package.json`** through hash-verified temporaries and publish a generation last. After off, compare both hashes exactly; preserve and fail on mutation.

### VM profile and prerequisite investigation

Codex provisions after explicit D10 authorization, using the wizard or `vmcli VM Create ... -c other-64`. D11 additionally requires its own authorization and that provisioned VM. The proposed profile requires hardware 22, UEFI/Secure Boot off, 1 GiB/1 vCPU, SATA/e1000, HPET, no USB and reference 3D/RTC/unattended-start settings. Require exactly `monitor_control.restrict_backdoor = "TRUE"` under 0017-D19; preflight rejects an absent, false or conflicting value. D11's vmmouse checks use that setting. Adoption is confirmed; acceptance under ULM and working kernel vmmouse are not a CPL3-enforcement probe. Require `pciBridge0.present`, and bridges 4–7 present with `virtualDev=pcieRootPort`, `functions=8`. Record creation method. Add VNC enabled, loopback IP, a reserved port 5901–6001, no password/key and no keyMap override. Initial oracle supports recorded 1024x768; another mode needs a reviewed oracle.

Reject contradictory/duplicate configuration, occupied port, unexpected devices, encrypted/unreadable configuration or escaping paths. Verify the listener belongs to this VM and binds only loopback before connecting. Bound VMX to 1 MiB, manifests/journals to 256 KiB and owner records to 16 KiB; lane-generated records have versioned schemas. No automatic firewall change.

Before guest implementation, D11 must verify the following under the team lock; failed prerequisites block the cases until a reviewed choice resolves them:

- Reliable off/running/suspended/transition and completed-power-operation indicators; absence from `vmrun list`, elapsed time and repeated snapshots alone are insufficient. Verify crash/timeout recovery and command-job lifetime as specified below.
- Listener ownership, complete serial epochs and (recommended D5) live reads with bounded delivery; Raw fidelity at reference 3D settings; repeated incremental and non-incremental requests on one connection on static and changing screens. An unchanged screen may leave an incremental request pending ([RFB §7.5.3](https://www.rfc-editor.org/rfc/rfc6143.html#section-7.5.3)); test its response after a controlled change, without issuing a second pending request.
- Verify the setup priming contract below and that the absolute pointer stays at its expected position across VNC connection, suspend and resume. Unexpected pointer movement requires a reviewed oracle rule, never a mask. Repeated-update stalls require a reviewed/confirmed reconnect policy and revised connect budget, not an automatic fallback.
- Byte-identical staged image/descriptor after a power cycle, plus both running and suspended PowerOff recovery paths. Rebuild identity proves neither. Resume responsiveness establishes no guest clock/Tools support.

### Exact guest evidence

Under recommended D5, each initial/restarted boot supplies its fresh readiness before input; validate the entire epoch again after off. The alternative policy would instead defer serial verdicts, including shell/console markers, until off, while retaining pixel fences and requiring all epochs to remain available. Record the confirmed policy in the lane profile; no runtime fallback flag.

The supported first oracle requires merged 0017c and absolute vmmouse; PS/2-only packages are outside this lane. Use schemas at `838c3b6` from `kernel/src/{main,acpi,apic,smp,timer,clock,pci,drivers,ps2,userspace,vmmouse}.rs`. Require these lines exactly once in order, with `elapsed_ms < 1000` (0017b's VMware threshold):

```text
MIRROR_PS2_INIT elapsed_ms=<u64> clock=hpet selftest=0
MIRROR_KEYBOARD_READY transport=i8042 set=2 irq=1
MIRROR_MOUSE_READY transport=i8042 packet=3 irq=12
MIRROR_VMMOUSE_READY mode=absolute
```

Reject VMMOUSE_SKIPPED/FALLBACK; source `838c3b6:kernel/src/vmmouse.rs:289-297`, called after MOUSE_READY at `main.rs:334,344`. The centered POINTER_READY precedes consumption of absolute position events (`main.rs:579-607`, `pointer.rs:26-31`); D11 must verify later pixel stability. Unrecognized package/oracle combinations block.

Reject every PS2_TIMEOUT, keyboard/mouse skip, malformed/duplicate or unknown member of a checked family, and unexpected fallback/fatal/trace/test output. Apply 0013's boot requirements: BOOT_OK/framebuffer readiness, configured enabled/online CPUs, xAPIC, LAPIC timer, no ACPI skip/table skip, PCI omitted=0 and AHCI/NIC/SVGA records. For the proposed one-vCPU profile, the observed IOAPIC line is `MIRROR_APIC_IOAPIC_ID index=0 firmware=1 hardware=0`, before APIC readiness. Record 42/34 PCI counts and flag differences; do not turn informational observations into universal constants. Require in order:

```text
MIRROR_AHCI_READY sectors=2097152 readonly=1 port=0
MIRROR_AHCI_PROBE_OK fixture=0 reads=1
MIRROR_AHCI_CLEANUP_OK dma_reclaimed=1
```

Rust lane assertions use these VMware values; `common.ps1::Assert-MirrorAhciMarkers` assumes QEMU's 2048-sector disk. NIC catalog presence is not networking functionality.

### Pixel and input contract

Match packaged-source glyphs, geometry and UI tokens. Shell readiness matches `Shell::paint`'s MIRROR/Native desktop/Esc and welcome glyph regions plus centered surface offset. BOOT_OK/static pixels alone are insufficient: `input::Session::new` drains before shell execution. Under recommended D5, wait for live absolute-vmmouse readiness and rendered shell readiness. Under the post-off alternative, wait for rendered shell readiness using the ancestry-validated vmmouse package; verify READY and no SKIPPED/FALLBACK from the preserved epoch after off before any pass verdict. Once the selected policy's pre-input readiness fence is met, send exactly one RFB PointerEvent with buttons=0 at framebuffer (512,384), before Escape. Its write has a 100 ms cap within the existing readiness/case deadline; failure aborts without resending. Record it as setup priming, with no expected response or extra frame request: the host may drop it or deliver the same center position. Repeat once on a new guest-restart epoch, never on suspend/resume or a same-epoch reconnect. Send Escape once, then match the console header, initial two history rows and empty input; `run_console` drains before rendering. Require these serial lines in this order, not necessarily adjacent; other records must match their schemas:

```text
MIRROR_SHELL_CLEANUP_OK apps_reclaimed=1 outcome=Exit(0)
MIRROR_SMP_IPI_OK phase=after_desktop cpus=1 rounds=4
MIRROR_POINTER_READY x=512 y=384 width=1024 height=768
MIRROR_CONSOLE_READY input=ps2 display=1
```

`framebuffer.rs::{ConsoleGeometry,glyph,draw_console_history,draw_console_input}` and `console.rs::{Console::process,Text::counter,parse}` define the oracle. At 1024x768: history origin (48,136), row spacing 24, prompt text x=72, edit origin (72,664), scale 2/advance 12. Compose the pointer using `mirror_ui_tokens::CURSOR` and `Driver::draw_cursor`: 15×19 at (512,384), X writes RGB(3,6,10), O writes text color RGB(236,241,249), and dots preserve the scene. Require that stationary overlay, including over blank rows; mask nothing. After setup priming the lane sends no pointer events. Concurrent interactive input is prohibited.

Before Enter require exact `status`, blank suffix and caret. After one Enter require empty input, unchanged prior history and exactly three appended rows: prompt `status`, `Timer ticks: <u64>`, `Keyboard IRQs: <u64>`. Validate decimal glyphs, 1–20 digits/u64 range/no leading zero except zero; do not predict counters. Echo uses `echo ` plus a 16-character lowercase hex run sentinel: match its edit text, prompt and exact output, retained after resume. Reject unknown commands, wrong/doubled/missing letters, extra rows, input-loss notices, stale/partial frames and sentinel leakage to serial. No OCR or guessed tolerance.

Send key-up immediately after each successful key-down write, without an intervening wait/frame/query. From starting down to completing up allow at most **200 ms**, with each write at most 100 ms; a longer gap is an ambiguous failure and gets no resend. Always attempt immediate bounded release on error. This stays below 0018's documented 500 ms VMware typematic delay without relying on benchmark input timing.

### Cases and bounds

| Case | Sequence after validated off state/staging |
| --- | --- |
| boot | Start once; boot/shell fences; Escape; console fences; exact status; evidence; stop hard once; prove off and check artifacts. |
| suspend-resume | Boot through status; exact echo; preserve history/serial; close VNC; suspend hard once; prove suspended; dwell 2 s; start nogui once; reconnect; same history/sentinel/boot epoch and no fatal marker; new exact status; stop/off checks. |
| restart | After 0058a's contract is confirmed and incorporated: checked boot/status; exact restart edit; Enter once; distinct boot epoch and readiness; console/status again; stop/off checks. No reset/repeated Enter/start rescue. |

The suspend history grows 2→5→7→10 rows, below capacity 12. Continuity preserves the original boot gate after resume; a reboot fails this case. No clock, timer-rearm or Tools support is inferred.

| --- | --- |
| Active case including staging | 900 s; busy lock fails immediately. |
| Package validation/staging; state/listener phase | 120 s; 15 s, at most 32 queries. |

### Acquire-only lock and same-run recovery

New lane/package invocations atomically create the team directory, retain the four readable owner fields plus `lane_schema=1`/`lane_kind=vm|package`/`lane_run=<id>` and a fresh lease identifier, and hold an exclusive write/delete-excluding handle on `owner.txt` throughout execution/finalization. An unreleased directory is busy for new work, including the same nick/task. An owner's final valid `released=<UTC time>` line makes its generation free under the team protocol, whether it is a manual or lane record. A new case or either Recover may detach that released generation using the procedure below and atomically create a fresh lease; it never erases the release line and reuses the old lease. Detachment targets the verified directory identity, not merely the reusable pathname, and cannot rename or delete a successor after a race. Failure to detach/acquire within the state-phase cap returns busy with evidence, even though the old record is released. No age/PID-based takeover or rewriting an unreleased foreign record.

Before staging, durably journal `preparing` under LaneRoot with operator/run, original worktree (provenance only), bound VMX/root, paths and last proven state. Record each power intent and dispatch time before dispatch, including restart Enter; partial staging is invalid. On error, release keys and preserve the first failure. A positively running VM may receive one cleanup stop only after previous power intents are reconciled.

One long-lived Rust controller owns the lease and every vmrun child. Assign each child before execution to a Windows [kill-on-close job](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) whose sole controlling handle belongs to the controller; disallow breakaway. Journal the controller/job identity and every directly created worker's PID/start time while suspended, before allowing execution; descendant membership must remain in that job. D11 must verify that all command workers are covered while VMware's service/vmware-vmx remain outside the job. Timeout/cancellation kills command workers, never vmware-vmx. If this separation cannot be demonstrated, guest cases and controller recovery stay disabled together; D11 is performed manually by the owner under today's team rules.

For an unresolved prior intent, reconciliation first establishes that its command job has no live workers/descendants, checking PID plus start time rather than PID alone; after a controller restart, also prove the prior recorded controller has exited. The current controller remains alive and holds the lease during its own cleanup. It then waits out the 60 s intent budget (a full 60 s if elapsed time cannot be trusted across restart) and reads D11's verified completion/state indicators twice within the state-phase cap. **Time and matching snapshots are not proof by themselves:** D11 must identify a terminal completion/cancellation rule that also excludes later work accepted by VMware's service. Validate it by killing start/stop/suspend workers before dispatch, after dispatch/acknowledgment and during transition; after the claimed terminal state, observe for 120 s with at most 240 polls and require no late VM process, new vmware.log session or state change. The mechanism evidence and all injection traces are prerequisites; a quiet observation window alone cannot pass. Until this rule succeeds, treat the VM as transitioning even when off/suspended is observed. The owner retains the lock and posts evidence in chat; it may rerun Recover after the intent budget, but elapsed time never authorizes a repeat power action. Cameron decides any other action. Apply the rule to failures and every recovery path.

Codex runs recovery from its own current checkout using the canonical LaneRoot record; it never needs the original worktree. `-Recover <run-id>` verifies the recorded operator/run and binding, obtains the exclusive handle on its retained **unreleased** lane lock, or atomically acquires a fresh lease when the directory is absent or validly released as above. A released lease is never taken back, even for the same run. Concurrent/active holders fail. Missing or mismatched run identity blocks, rather than borrowing another lock. Plain Recover only reconciles and finalizes a proven-off run, or journals proven suspension and releases; running/unknown states remain locked with instructions to invoke PowerOff. Partial/absent staged files are evidence, never repaired silently.

Explicit **`-Recover <run-id> -PowerOff`** holds that same lease in one process through reconciliation, power actions and finalization. Once state is known: off needs no action; running gets `vmrun -T ws stop <bound-vmx> hard` once; suspended first copies the complete current serial epoch into durable run evidence, then gets `start <bound-vmx> nogui` once and, after proven running/completion, `stop <bound-vmx> hard` once. Failed serial preservation prevents start because VMware may replace the file. Journal each action, prove off, preserve the failed run's verdict, then finalize/release. No repeat of an ambiguous action, reset, `.lck` deletion or separate shell handoff. D11 must verify both paths and interrupted-command reconciliation before guest cases and recovery are enabled together; otherwise guest cases stay blocked, with evidence for Cameron.

If the recorded operator is unavailable, follow the team's stale-lock rule and ask in chat. Only Cameron's explicit authorization naming the run/root, original operator, replacement operator and recovery scope permits replacement. After verifying that run and obtaining its exclusive lease, append the authorization text/reference and both identities to LaneRoot and append the replacement's nick/authorization reference to `owner.txt` before acting. Preserve the original ownership history; the current holder is explicit. Never impersonate the old operator or write its worktree. The separate proposed VMR-D6 exception requires confirmation and team-rule documentation, not general adoption. No authorization means no takeover.

Release the lane-created directory only at these points: packaging ended with no live build; durable `finalized-off` (pass or fail); a reconciled suspended failure; or those same off/suspended outcomes in Recover. Suspended release first preserves `suspended-needs-recovery`; its journal prevents restaging/new cases. Running, unknown or unresolved states retain the lock; planned successful suspend/resume retains it across the dwell. Release must preserve run identity and cannot remove a successor's lock.

Use one release procedure for normal completion and both recovery modes. Persist the eligible final state and release intent first. Through the still-held owner handle append the lane run/lease identity and the owner's final `released=<UTC time>` line and flush it; record `lock_release=owner-record` with that identity/time in the run journal and `final.json` before closing the handle. The operator posts `lock released`. Never delete contents at the shared acquisition pathname. If permitted, atomically rename the verified released directory generation to a unique non-existing sibling `qemu.released.<unique-id>`, using directory identity and no-replace semantics so a competing taker cannot redirect the operation to a successor. Only after that detachment may optional deletion remove contents at the verified sibling path; record `lock_release=detached` with the sibling identity/path, then `removed` if cleanup completes. A new taker uses this same detach-first procedure for a released record, then atomically creates its fresh `qemu` lease. Rename denial leaves the released owner record intact for a later taker; deletion denial after detachment leaves only a reported cleanup artifact, which cannot block acquisition. A crash between deleting the detached owner file and its directory therefore cannot create an ownerless directory at the shared acquisition pathname. A crash before the release record is durable requires Recover; a crash after it never authorizes retaking the old lease. A lagging journal field is reconciled against the owner record or proof that a successor/absence replaced that generation, without changing the VM verdict.
