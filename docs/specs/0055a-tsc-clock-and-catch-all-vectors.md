# 0055a: A TSC clock calibrated against the HPET, and catch-all vectors

Status: drafted and implementing on `claude/0055a-tsc-clock` (2026-11-05, claude).
Split from 0055 (`roadmap-replan.md:127`, RD24); it takes 0055-D1 to D6, and 0055b continues from D7.
Ledger: S10 (the TSC here needs the HPET; a source without one stays 0055b), S7, S7a, S7b, S17. Related: 0013 (scope notes at `0013-firmware-and-pci-tolerance.md:27-29`), 0016a (`0016a-guarded-stacks.md:25`), 0019a (0019-D5's `since_entry_ns=none`), 0051 (point 9's cross-CPU clock).

## Goal
`clock::snapshot` reads the TSC instead of an uncached HPET register once the TSC has been calibrated against the HPET and every online CPU's TSC agrees with the BSP's. A VM exit per clock read becomes a plain instruction. Every vector without a handler gets a gate, so a stray interrupt is acknowledged and counted instead of becoming a #GP crash. A #GP, #NP, #SS or #TS that an external event caused is no longer blamed on the user thread it happened to interrupt.

## Non-goals
- The x2APIC handoff. VMware and QEMU both hand off in xAPIC mode (0013 tests 14 and 16, RD11), so no target needs it; it moves to 0055b with PCAT_COMPAT=0, LINT1 on the BSP only, and calibrating the LAPIC timer against the HPET (D6).
- A time source without an HPET (S10 stays with 0055b), wall-clock time (0056a) and suspend/resume resync (0087c).
- `since_entry_ns` in 0019a's perf clock milestone. With a calibrated TSC it becomes possible, and it follows as a 0019 change.
- Masking a stray level-triggered source that storms. Every IOAPIC input outside Mirror's three routes stays masked (`apic.rs`, `Controller::configure`).

## Design
| ID | Decision |
| --- | --- |
| 0055-D1 | **Eligibility.** The TSC is calibrated only when the HPET clock is published, CPUID.1:EDX.TSC is set, and either the invariant-TSC bit (CPUID.80000007h:EDX[8]) or the hypervisor bit (CPUID.1:ECX[31]) is set. Calibration still has to pass D2, so a VM whose TSC rate wanders is rejected there. Rationale: Mirror targets VMs (G3). VMware and QEMU's TCG present a constant-rate TSC whether or not they set the invariant bit, and Linux trusts VMware's TSC the same way (`arch/x86/kernel/cpu/vmware.c`, `vmware_set_capabilities`). On bare metal without the invariant bit, a P-state change could alter the rate, so such a machine keeps the HPET. |
| 0055-D2 | **Calibration.** On the BSP with IF clear, right after `clock::init`: three windows of 20 ms on the HPET clock. Each endpoint brackets one HPET read between two `lfence; rdtsc` reads and uses their midpoint, retried up to 8 times until the bracket is at most 50 µs. Each window gives a rate. The spread, (max - min) / median, must be at most 1000 ppm, and the rate, taken over the whole 60 ms span, must lie in 100 MHz..=20 GHz. The conversion is `ns = base_ns + (delta * mult) >> 32` with `mult = (10^9 << 32) / hz`. Boot cost is about 60 ms. Rejected alternatives: CPUID leaf 0x15 or VMware's 0x40000010 frequency (QEMU's TCG reports neither, and a cross-check can come later); a single long window (no stability check). |
| 0055-D3 | **Cross-CPU agreement.** Just before the BSP releases the APs, it takes a reference pair (TSC, HPET ns). Each AP, before going ONLINE, takes its own bracketed pair and records `skew = tsc_ns(ap) - hpet_ns(ap)` relative to that reference, so a rate error contributes only for the startup interval. The largest absolute skew, and the count of checked APs, are kept in atomics. Limit: 250 µs, a quarter of 0051 point 9's 1 ms cross-CPU tolerance. Rejected alternative: Linux's pairwise TSC warp test (`arch/x86/kernel/tsc_sync.c`), which needs a BSP and AP rendezvous for each CPU. |
| 0055-D4 | **Selection.** After SMP startup, with the APs idle, `clock::select_tsc(online)` publishes the TSC only if calibration passed, every online AP checked in, and the largest skew is within the limit. `base_ns` is the higher of the highest snapshot so far and a fresh bracketed HPET reading, so time continues without a step back. From then on `snapshot` uses the TSC on every CPU and reports `resolution_ns = ceil(10^9 / hz)`. The highest-value rule from 0051 point 9 now keeps nanoseconds, not HPET counts. A read more than 1 ms behind is still fatal. The restart and crash stopwatches keep reading the HPET counter directly, without the regression check (0058a D7). |
| 0055-D5 | **Catch-all gates.** Each vector 48..=254 without a handler (that is, all but 0x80, 240, 241 and 242) gets a DPL0 interrupt gate to its own stub, so the IDT has 203 more gates and none missing. The handler, on any CPU: with the APIC enabled and the vector's bit set in this CPU's LAPIC ISR, it was delivered, so it sends an EOI and counts it as delivered. Otherwise it is a kernel `int n` and is counted as software. It never prints, locks or allocates. An AP dispatches these vectors once ONLINE, like its timer. This also covers the BSP's missing inherited-IRR check (`apic.rs`, `prepare`, compared with `init_secondary`). A user `int n` still gets #GP from the DPL0 gate, and that is the user's fault. |
| 0055-D6 | **EXT faults.** A #TS, #NP, #SS or #GP (vectors 10-13) taken at CPL3 with error-code bit 0 (EXT) set came from delivering an external event, not from the user's instruction. It takes the fatal path instead of `userspace::fault`. |

**Markers**, closed-world in `Assert-MirrorTsc` (`common.ps1`):
- Every flavor, after `MIRROR_CLOCK_READY` or `MIRROR_CLOCK_SKIPPED`: `MIRROR_TSC_CALIBRATED hz=<n> spread_ppm=<n> invariant=<0|1> hypervisor=<0|1>`, or `MIRROR_TSC_SKIPPED reason=no_clock|no_tsc|not_constant|unstable|range|bracket`.
- Every flavor, after `MIRROR_SMP_READY` or `MIRROR_SMP_SKIPPED`, only when calibrated: `MIRROR_TSC_READY cpus=<online> max_skew_ns=<n> resolution_ns=<n>`, or `MIRROR_TSC_REJECTED reason=ap_skew|ap_unchecked cpus=<online> checked=<n> max_skew_ns=<n>`.
- Boot-smoke: `MIRROR_TSC_POLICY_OK` once; after READY, `MIRROR_TSC_OK elapsed_ns=<n> reference_ns=<n>`; `MIRROR_VECTOR_CATCHALL_OK gates=203 software=1 delivered=<n>`, where `delivered` is the number of CPUs that answered a self-test IPI on vector 0x60 (the online CPUs with the APIC, else 0).
- Every flavor: `MIRROR_IDT_READY` gains `catchall=203`.

## Tests
- Boot-smoke policy (`MIRROR_TSC_POLICY_OK`): eligibility for each CPUID combination; median, spread and range rejection; `mult` and the conversion at the range bounds (no overflow, monotonic); skew evaluation; the EXT classification for vectors 0-31 with and without bit 0; and the catch-all vector set (203 vectors, exactly the unhandled ones).
- `run.ps1 -Smoke` with no switches, `-CpuCount 4`, `-ExtendedCpu -CpuCount 8`, `-BaselineCpu`, `-LegacyPic -CpuCount 4`, `-NoHpet` and `-Fault ClockActivation`. `Assert-MirrorTsc` checks the family's counts and order; the script recomputes the eligibility (`hypervisor` or `invariant`), the hz range, spread ≤ 1000, `cpus=` against `MIRROR_SMP_READY`'s `online=`, `max_skew_ns` ≤ 250000 for READY, and `|elapsed - reference|` ≤ 0.5% of `reference` for `MIRROR_TSC_OK`.
- New fault `TscSkew` (`mirror.test=tsc-skew`, `-CpuCount 2` or more): each AP adds 10 ms to its measured skew, so the line is `MIRROR_TSC_REJECTED reason=ap_skew`, the HPET stays the source and the boot passes. Every other case rejects `reason=ap_skew`.
- `MIRROR_VECTOR_CATCHALL_OK` in every smoke boot: the BSP runs `int 0x50` (software, no EOI), then sends vector 0x60 to every online CPU, itself included, and waits on a bounded clock until each one's delivered count rises and the BSP's ISR bit for 0x60 is clear.
- Captures (`-CpuCount 4`, both pointer modes) and the hygiene probe call `Assert-MirrorTsc -Smoke $false`, which requires READY. The image scans require `MIRROR_TSC_CALIBRATED hz=`, `MIRROR_TSC_SKIPPED reason=`, `MIRROR_TSC_READY cpus=` and `MIRROR_TSC_REJECTED reason=` in the default and trace kernels, and forbid `MIRROR_TSC_POLICY_OK`, `MIRROR_TSC_OK` and `MIRROR_VECTOR_CATCHALL_OK`.
- Then the full `test.ps1`.
