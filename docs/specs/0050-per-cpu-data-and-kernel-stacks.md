# 0050: Per-CPU data and per-thread kernel stacks

Status: draft (revised after claude's review of 08d9c9d)
Depends on: 0030a (threads live in its global table; its 0030-D2 deferred completions carry this spec's stack allocation). RD21 must be confirmed with or before this spec (open question 3). Ordered third in Phase 1 (roadmap-replan.md), before kernel heap v2 and 0051.
Ledger: decisions.md Phases row 1 (per-CPU data), S6 as amended 2026-10-11 (no syscall), S6a (INT 0x80 stays the legacy shim; SYSCALL is 0021), S7/S7a/S7b (marker gating). Related: I6 (0051 builds on this), S17 (0051's NMI stop builds on D1), 0016a's guarded-stack layout (its Interfaces item 1).

Line references are at HEAD 970e48c.

## Goal
The kernel gains three things it needs for SMP userspace and later phases, built once:

1. **Per-CPU data.** Today there is no per-CPU pointer: state lives in static arrays (`SLOTS`, smp.rs:107; `SECONDARY_TSS/GDT`, interrupts.rs:186-190) and "which CPU am I" is a CPUID re-read plus a linear scan (smp.rs:597-605). After this spec each CPU runs with IA32_GS_BASE pointing at its own `CpuData`, and `current_cpu()` is a read, not a scan.
2. **Per-thread kernel stacks.** Today every user thread traps onto the BSP's single 64 KiB RSP0 stack (stacks.rs:119, installed once per session at userspace.rs:697/:1256/:2033). After this spec each thread owns a guarded kernel stack, allocated by the scheduler at create and freed at exit, and the running thread's stack is the TSS RSP0.
3. **A post-seal kernel VA allocator.** Today `map_kernel_page` is sealed at `share_with_secondaries` (paging.rs:606-608) and only two prepared windows survive: the 2 MiB single-page shared window (paging.rs:43-45) and the 16 MiB heap window. After this spec a third pinned window parcels out guarded VA ranges at runtime — the thread stacks are its first client.

The trap-frame-retention scheduling model is unchanged: a suspended thread keeps only its `TrapFrame` and FPU state (interrupts.rs:196-197), and the kernel continuation is still rebuilt on the scheduler stack, so nothing on a thread's kernel stack is live once it suspends. The SYSCALL entry is unchanged and belongs to 0021 (RD21).

## Non-goals
- The SYSCALL entry rework (0021; RD21 writes it per-CPU from the start on this spec's GS discipline). EFER.SCE stays off (0016b). readme.md:38's clause naming that rework in 0050 is reworded when RD21 is confirmed.
- Userspace on APs, per-CPU run queues, and moving the `ACTIVE*` statics into `CpuData` (0051). The scheduler still runs on the BSP with IF=0.
- Changing the suspend/resume model to frozen kernel stacks (retention is kept; a later spec can freeze stacks on top of these per-thread stacks if deep in-kernel blocking wants it).
- Shrinking or restacking the BSP scheduler stack, the IST stacks or the AP slot stacks (0016a's layout, stacks.rs:31-46). The BSP RSP0 stack's role is in D2.
- Charging thread stacks to their process: they are uncharged global kernel memory in this spec, consistent with heapv2-D3's "boot and global allocations stay uncharged"; whether to charge them is heap v2's or 0054a's call.

## Decisions
| ID | Decision | Status |
| --- | --- | --- |
| 0050-D1 | Per-CPU data over `swapgs`, with the full GS state machine. `CpuData` is a static `[CpuData; 64]` indexed by SMP slot (nothing per-CPU is ever allocated: APs cannot allocate, smp.rs:3-5), holding the slot back-reference, the current thread and per-CPU scratch such as today's `MIRROR_USER_KERNEL_RSP` (interrupts.rs:198-199). MSR roles: whenever kernel code runs, IA32_GS_BASE (0xC0000101) holds this CPU's `CpuData` and IA32_KERNEL_GS_BASE (0xC0000102) holds the inactive user base. (a) CPL3 entry (interrupts.S:93-118): save the selectors, the FS base and the user GS base, null the FS/GS selectors (loading a user or null selector overwrites the hidden base, so the selector work precedes the swap), zero the FS base, then swapgs. (b) CPL3 exit: reset KERNEL_GS_BASE to `CpuData`, swapgs, load the user selectors, write IA32_GS_BASE = frame.gs_base, then iretq; user GS selector loads stay a supported contract (MIRROR_TLS_READY selectors=1, interrupts.rs:248). CPL0 exits never write IA32_GS_BASE. (c) The IST vectors 2, 8 and 18 (interrupts.rs:322-326) get a paranoid entry: read IA32_GS_BASE, swapgs only if it is not kernel-half (valid user bases are below 2^47, interrupts.rs:262-265), and undo the swap on exit — an NMI or #MC can interrupt the restore epilogue with user GS live (interrupts.S:90-92), and 0051's S17 NMI stop must identify its CPU at any instruction. (d) `return_from_user` (interrupts.rs:820-823), `mirror_resume_kernel` (userspace_entry.S:64-71) and `load_descriptors` (interrupts.rs:445-453) stop zeroing IA32_GS_BASE; `load_descriptors` may zero it only before `CpuData` is installed. (e) The BSP installs its GS base after `interrupts::init`; each AP writes IA32_GS_BASE after `init_secondary` succeeds (smp.rs:493-495), reads it back and records the result in its Slot, which the BSP checks before printing MIRROR_CPU_DATA_READY. The kernel-mode TLS assertions (`kernel_tls_clean`, interrupts.rs:274-296) now require GS.base == this CPU's `CpuData`, and the self-test's CPL0 round trip (interrupts.rs:838-912) is rewritten to save and restore `CpuData` around it (the user base lives in KERNEL_GS_BASE while the kernel runs). `smp.rs`'s CPUID rescan (:597-605) stays only as the early-boot fallback before GS is live. Rejected alternative: keep rescanning CPUID (every scheduler operation pays a scan once APs run userspace). | proposed |
| 0050-D2 | Per-thread kernel stacks of 64 KiB, guarded to 0016a's layout rules (its Interfaces item 1; stacks.rs:1-10: one unmapped page each side, verified before and after), allocated from the D3 window and freed by the scheduler only. Allocation and free never run in a trap handler: SYS_THREAD_CREATE becomes a deferred continuation in the MemoryRequest/`complete_memory` pattern (userspace.rs:964-972, :1159) — the handler parks the creator, and the scheduler, with the kernel root active (prepare_kernel_update requires CR3 == ROOT, smp.rs:792-795) and the frame allocator in hand (userspace.rs:889), allocates the guarded stack, builds the thread and completes the syscall with the TID or -11 (EAGAIN). The scheduler frees a thread's stack at exit, after the exiting thread's handler has unwound (nothing on it is live past suspend, interrupts.rs:194-197), and frees every thread's stack at process teardown; a stack is never freed while it is the installed RSP0. The BSP's 64 KiB RSP0 stack (stacks.rs:37) keeps its role as the trap stack installed whenever no thread runs (idle and kernel context), so `set_kernel_stack`'s contract (interrupts.rs:684-686) holds across frees and KernelStackOverflow (stacks.rs:150-184) still tests a live stack. At dispatch the TSS RSP0 is set to the thread's stack top (interrupts.rs:687-702 moves from once-per-session to once-per-dispatch). Stacks are uncharged global kernel memory (see Non-goals); the boot-smoke frame and window baselines at session drain (0030-D5) prove they return. 64 KiB matches the proven RSP0 depth; boot-smoke adds a high-water mark to inform a later shrink. Rejected alternatives: allocation inside the create handler (no root, no allocator, no legal shootdown there); free at join (keeps 16 frames per exited-unjoined thread pinned for no reader). | proposed |
| 0050-D3 | A post-seal kernel VA window: 32 MiB at 0xffff_d400_0000_0000 — an unused PML4 slot (in use: d000 heap, d100 stack arena, d200 shared, d300 device/firmware, c000 the smoke test page) — with a const assert in the style of apic.rs:31-33 that it overlaps none of them, and a `kva_reserved()` refusal added to `map_kernel_page` and `unmap_page` beside `heap_reserved` (paging.rs:609-614, :675-680) so pre-seal mappings can never land in it. Its table hierarchy is pinned at init beside the heap window (the prepare_heap_window pattern, paging.rs:332-358): 16 page-table frames for 32 MiB, held on every boot. Sizing: 256 guarded stacks need 18 MiB with their guard gaps (72 KiB of VA each); the rest is reserve, and Phase 2 object storage is heap v2's arena, not this window. A page-granularity VA allocator parcels ranges whose stack allocations always include their two never-mapped guard pages. Mapping and unmapping go through batched leaf updates under `smp::KernelUpdate` (smp.rs:787-865), and `invalidation_range_valid` (smp.rs:636-658) whitelists the new window. Degraded mode: absent-to-present leaf maps need no remote invalidation (TLBs and paging-structure caches hold only present entries), so when the shootdown transport is unavailable — a configured AP left CANCELLED (smp.rs:259-266), which today fails soft — maps proceed locally and userspace still starts; an unmap that cannot collect every acknowledgement quarantines the range (the VA and frames are kept, never reused) and reports it in `MIRROR_KSTACK_OK`'s `kstack_quarantined=` field. On a 1-CPU boot, where the seal is never set (smp.rs:400-406), the window works through the same API. Rejected alternative: extend the shared window (single-page, 2 MiB, paging.rs:241-303 — 256 guarded stacks need 18 MiB of VA with gaps). | proposed |
| 0050-D4 | Markers. `MIRROR_CPU_DATA_READY cpus=<n>` and `MIRROR_KVA_READY base=0xffffd40000000000 size=33554432` print once per boot in every flavor (content-free); both join test.ps1's default and trace `$required` lists (test.ps1:35-40), and common.ps1 checks each exactly once with its full field list after the SMP line, recomputing cpus= from MIRROR_SMP_READY online= (the MIRROR_SMP_READY pattern, run.ps1:78-80, common.ps1:402-437). `MIRROR_KSTACK_OK threads=16 watermark_pages=<n> kstack_quarantined=<n>` is boot-smoke only, prints once per init-pair session (twice per smoke boot) after its thread battery, with 1 <= watermark_pages <= 16 required; it joins both `$forbidden` lists and capture.ps1's absent list (capture.ps1:695-698). `MIRROR_KSTACK_GUARD guard=<hex>` is boot-smoke only, printed only by the ThreadStackOverflow fault case (acceptance 3) and rejected in every other scenario. | proposed |

## Interfaces
- `kernel/src/cpudata.rs` (new): `CpuData`, the static table, boot/AP install, `current_cpu()`.
- `kernel/src/kernel_va.rs` (new): the D3 window allocator and its degraded-mode rules; `stacks::map_guarded` gains a post-seal path on it (the pre-seal path and its contract, stacks.rs:231-235, stay for boot stacks).
- `kernel/src/interrupts.S`, `kernel/src/userspace_entry.S`, `kernel/src/interrupts.rs`: the D1 state machine (entry/exit/paranoid-IST/suspend paths), the self-test rewrite, per-dispatch RSP0, `MIRROR_USER_KERNEL_RSP` moves into `CpuData`.
- `kernel/src/smp.rs`: the AP install point (:493-495), a new boot-smoke IPI operation (for example OP_READ_CPU_DATA) in `operation_valid` (:671-685) and `handle_ipi` (:919-997) for acceptance 2, and the invalidation whitelist (:636-658).
- `kernel/src/sched.rs` (0030a): the deferred create-continuation and the exit/teardown stack frees (0030-D2's deferred completion carries them); dispatch installs the thread's RSP0.
- `kernel/src/paging.rs`: the third prepared window and the `kva_reserved` refusals.
- `kernel/src/boot.rs`: the `thread-stack-overflow` token beside the existing modes (:176-189).
- Scripts: run.ps1 gains `-Fault ThreadStackOverflow` (ValidateSet :25, $testMode :288, $fatalKernelFault :511, and the cr2 check against MIRROR_KSTACK_GUARD, the :928 pattern); test.ps1 adds the case in both profiles and the image-list changes of D4; capture.ps1's absent list gains MIRROR_KSTACK_OK and MIRROR_KSTACK_GUARD; common.ps1 gains the exact-once checks.
- readme.md: :7 (thread stacks), :201 (the INT3 test's "cleared state" becomes the CpuData invariant), :219 and :305 (KernelStackOverflow's target wording), :241 ("User entries use TSS.RSP0 and a dedicated guarded 64 KiB kernel stack" becomes per-thread stacks), :497 (THREAD_CREATE's -11 row gains stack-allocation failure) and :560 ("Kernel execution clears the user bases" becomes the D1 state machine). AGENTS.md's fault-injection steps gain the case under their existing rules.

## Acceptance tests
1. The existing battery passes on the new entry path: threads, sync, TLS (a user non-null GS selector and base survive a syscall, a preemption and a suspend), FPU, paging and scheduler checks, with `MIRROR_TLS_READY`/`MIRROR_TLS_KERNEL_OK` asserting the D1 invariants.
2. Per-CPU data: OP_READ_CPU_DATA proves on the BSP and every online AP that GS resolves to that CPU's `CpuData`, matching its `SLOTS` entry; `MIRROR_CPU_DATA_READY cpus=` equals the recomputed online count. A boot-smoke probe sets IA32_GS_BASE to a user-range value, runs `int 2`, and checks that the handler saw this CPU's `CpuData` and that the value is restored on return; the IST probe (MIRROR_IST_OK) is also run with a nonzero user-style GS base installed at CPL0.
3. Thread stacks: two threads interleaving syscalls trap onto distinct stacks (entry RSP readback inside each thread's guarded range, boot-smoke only). `-Fault ThreadStackOverflow` (`mirror.test=thread-stack-overflow`) allocates a stack through the D3 path, prints `MIRROR_KSTACK_GUARD guard=<hex>` then `MIRROR_TEST_EXPECT_FATAL vector=8`, walks the stack downward as overflow_rsp0 does, and faults with cr2 in the reported guard page, exiting 35 (the run.ps1:904/:928 checks follow). run.ps1 rejects MIRROR_KSTACK_GUARD in every other scenario; test.ps1 runs the case in both profiles.
4. VA allocator: a boot-smoke self-test allocates, maps, probes on every CPU (the heap.rs:304-311 pattern), unmaps and frees ranges with guard gaps intact, and checks exhaustion and partial-failure rollback against exact frame and window baselines. A degraded-mode case marks an AP failed before a session (the OP_GUARD_FAULT path) and checks that thread creation still works through local mapping, with `kstack_quarantined=` reported.
5. Stack-failure injection: a boot-smoke mode fails the Nth stack frame during SYS_THREAD_CREATE and during process creation; both fail with -11 (or the launch failure path) and restore the exact frame and window baselines.
6. Capacity: with 0030a, 256 threads across 64 processes each get a stack (the window's 18 MiB); creation beyond that fails EAGAIN with rollback, and the session-drain baselines hold.
7. Before merge (P8): the full `scripts/test.ps1` in debug and release, plus `test.ps1 -AgentDemo` while the agent-demo feature exists (RS6). All script changes land in the same commit.

## Dependencies
No new crates.

## Open questions
1. The thread-stack size: 64 KiB is proven; 32 KiB halves the 16 MiB full-capacity frame cost if the watermark allows. Decided after test 3's first measurements; the spec keeps 64 KiB until then.
2. The window size (32 MiB: 18 MiB of stacks plus reserve, 16 pinned page-table frames): confirm or adjust.
3. RD21 must be confirmed together with 0050: it removes readme.md:38's SYSCALL-rework clause from this scope and retires decisions.md:213's inferred placement. If it is not confirmed, this spec still builds no SYSCALL entry (EFER.SCE stays off); 0021 then adopts D1's GS discipline unchanged when it is written.
4. 0050 is built only after 0030a is confirmed (RD24) and its review findings are resolved; D3's sizing and test 6 follow 0030a's confirmed capacities rather than literals.
