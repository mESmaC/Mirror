# 0050: Per-CPU data and per-thread kernel stacks

Status: draft (revised after claude's reviews of 08d9c9d and 1117cca)
Depends on: 0030a (threads live in its global table; this spec's create continuation builds on 0030-D2's scheduler completion pass, and its exit-time frees ride 0030-D2's reap). RD21 must be confirmed with or before this spec (open question 3). Ordered third in Phase 1 (roadmap-replan.md), before kernel heap v2 and 0051.
Ledger: decisions.md Phases row 1 (per-CPU data), S6 as amended 2026-10-11 (no syscall), S6a (INT 0x80 stays the legacy shim; SYSCALL is 0021), S7/S7a/S7b (marker gating). Related: I6 (0051 builds on this), S17 (0051's NMI stop builds on D1), 0016a's guarded-stack layout (its Interfaces item 1).

Line references are at HEAD 970e48c.

## Goal
The kernel gains three things it needs for SMP userspace and later phases, built once:

1. **Per-CPU data.** Today there is no per-CPU pointer: state lives in static arrays (`SLOTS`, smp.rs:107; `SECONDARY_TSS/GDT`, interrupts.rs:186-190) and "which CPU am I" is a CPUID re-read plus a linear scan (smp.rs:597-605). After this spec each CPU runs with IA32_GS_BASE pointing at its own `CpuData`, and `current_cpu()` is a read, not a scan.
2. **Per-thread kernel stacks.** Today every user thread traps onto the BSP's single 64 KiB RSP0 stack (stacks.rs:119, installed once per session at userspace.rs:697/:1256/:2033). After this spec each thread owns a guarded kernel stack, allocated by the scheduler at create and freed at exit into a reuse pool, and the running thread's stack is the TSS RSP0.
3. **A post-seal kernel VA allocator.** Today `map_kernel_page` is sealed at `share_with_secondaries` (paging.rs:606-608) and only two prepared windows survive: the 2 MiB single-page shared window (paging.rs:43-45) and the 16 MiB heap window. After this spec a third pinned window parcels out guarded VA ranges at runtime — the thread stacks are its first client.

The trap-frame-retention scheduling model is unchanged: a suspended thread keeps only its `TrapFrame` and FPU state (interrupts.rs:196-197), and the kernel continuation is still rebuilt on the scheduler stack, so nothing on a thread's kernel stack is live once it suspends. The SYSCALL entry is unchanged and belongs to 0021 (RD21).

## Non-goals
- The SYSCALL entry rework (0021; RD21 writes it per-CPU from the start on this spec's GS discipline). EFER.SCE stays off (0016b). docs/specs/README.md:38's clause naming that rework in 0050 is reworded when RD21 is confirmed.
- Userspace on APs, per-CPU run queues, and moving the `ACTIVE*` statics into `CpuData` (0051). The scheduler still runs on the BSP with IF=0.
- Changing the suspend/resume model to frozen kernel stacks (retention is kept; a later spec can freeze stacks on top of these per-thread stacks if deep in-kernel blocking wants it).
- Shrinking or restacking the BSP scheduler stack, the IST stacks or the AP slot stacks (0016a's layout, stacks.rs:31-46). The BSP RSP0 stack's role is in D2.
- Charging thread stacks to their process: they are uncharged global kernel memory in this spec, consistent with heapv2-D3's exemption; whether to charge them is 0054a's call.

## Decisions
| ID | Decision | Status |
| --- | --- | --- |
| 0050-D1 | Per-CPU data over `swapgs`, with the full GS state machine. `CpuData` is a static `[CpuData; 64]` indexed by SMP slot (nothing per-CPU is ever allocated: APs cannot allocate, smp.rs:3-5), holding the slot back-reference, the current thread and per-CPU scratch such as today's `MIRROR_USER_KERNEL_RSP` (interrupts.rs:198-199). MSR roles: whenever kernel code runs, IA32_GS_BASE (0xC0000101) holds this CPU's `CpuData`; IA32_KERNEL_GS_BASE (0xC0000102) is scratch in kernel mode, and the user base lives only in the thread's frame. The invariant the paranoid entries rely on: whenever IA32_GS_BASE is not kernel-half, IA32_KERNEL_GS_BASE holds `CpuData` (established by (b)'s reset and by install). Rules: (a) CPL3 entry (interrupts.S:93-118): save the selectors, the FS base and the user GS base into the frame, null the FS/GS selectors (a selector load overwrites the hidden base, so selector work precedes the swap), zero the FS base, then swapgs. (b) CPL3 exit: reset IA32_KERNEL_GS_BASE to `CpuData`, swapgs, load the user selectors, then write IA32_FS_BASE = frame.fs_base and IA32_GS_BASE = frame.gs_base, then iretq; user GS selector loads stay a supported contract (MIRROR_TLS_READY selectors=1, interrupts.rs:248). (c) The IST vectors 2, 8 and 18 (interrupts.rs:322-326) get a paranoid entry: read IA32_GS_BASE, swapgs only if it is not kernel-half (valid user bases are below 2^47, interrupts.rs:262-265), and record the swap in the paranoid frame; the exit undoes exactly that swap, never combined with (b) or a CPL0 exit. The paranoid entry also saves and nulls a non-null FS selector and zeroes a non-zero FS base, restoring them on exit. An NMI or #MC can interrupt the restore epilogue with user GS live (interrupts.S:90-92), and 0051's S17 NMI stop must identify its CPU at any instruction. (d) Once `CpuData` is installed, no kernel-mode path loads the FS or GS selector except the CPL3 exit (before its base writes): CPL0 entries and exits, including the suspend continuation, leave both selectors, the FS base and both GS MSRs untouched and ignore the frame's selector and base fields (on Intel and QEMU TCG a selector load sets the hidden base to 0), and `mirror_resume_kernel` drops its FS/GS work (userspace_entry.S:64-71) because the CPL3 entry already left null selectors and a zero FS base. `return_from_user` (interrupts.rs:820-823) and `load_descriptors` (interrupts.rs:445-453) stop zeroing IA32_GS_BASE. (e) Install order: before install, both GS MSRs are 0 (load_descriptors also zeroes 0xC0000102) and fatal paths that can run before install use the CPUID scan and never read through GS. The BSP installs its GS base after `interrupts::init` and before `tls_ready` (main.rs:60-63); each AP installs after `init_secondary`'s descriptor load and *before* its `kernel_tls_clean` readback (smp.rs:493-495, interrupts.rs:613), which from then on expects GS.base == this CPU's `CpuData`; the AP's readback is recorded in its Slot and the BSP checks every Slot before printing MIRROR_CPU_DATA_READY. The self-test's CPL0 round trip (interrupts.rs:838-912) is rewritten: IA32_GS_BASE keeps `CpuData` and a null selector across the int3, the sentinels live in IA32_KERNEL_GS_BASE, and both are checked unchanged afterwards. `smp.rs`'s CPUID rescan (:597-605) stays only as the pre-install fallback. Rejected alternative: keep rescanning CPUID (every scheduler operation pays a scan once APs run userspace). | proposed |
| 0050-D2 | Per-thread kernel stacks of 64 KiB, guarded to 0016a's layout rules (its Interfaces item 1; stacks.rs:1-10: one unmapped page each side, verified before and after), allocated from the D3 window and freed by the scheduler only. Allocation and free never run in a trap handler: SYS_THREAD_CREATE becomes this spec's own deferred continuation, built on 0030-D2's scheduler completion pass — the handler parks the creator, and the scheduler, with the kernel root active and the frame allocator in hand (userspace.rs:889, :944), allocates the guarded stack, builds the thread and completes the syscall with the TID or -11 (EAGAIN). The scheduler frees a thread's stack at exit, after the exiting thread's handler has unwound (nothing on it is live past suspend, interrupts.rs:194-197), and frees every thread's stack at process teardown. Freed stacks are not unmapped: they go to the window's reuse pool (D3), so a free never needs a shootdown and never touches the installed RSP0. At dispatch the TSS RSP0 is set to the thread's stack top (interrupts.rs:687-702 moves from once-per-session to once-per-dispatch). The BSP's 64 KiB RSP0 stack (stacks.rs:37) stays installed as a placeholder whenever no thread runs, keeping `set_kernel_stack`'s contract (interrupts.rs:684-686); KernelStackOverflow exercises its guard, and ThreadStackOverflow is the live test (test 3). readme.md:219 and :305 are worded to match. Stacks are uncharged global kernel memory (Non-goals); the boot-smoke frame and window baselines at session drain (0030-D5) prove they return to the pool. 64 KiB matches the proven RSP0 depth; boot-smoke adds a high-water mark to inform a later shrink. Rejected alternatives: allocation inside the create handler (no root, no allocator there); unmap-on-free (a shootdown per exit can stall the scheduler for up to a timer tick, smp.rs:1002-1023, and is unneeded — reuse keeps the same VA and frames, so a stale translation on any CPU stays correct). | proposed |
| 0050-D3 | A post-seal kernel VA window: 32 MiB at 0xffff_d400_0000_0000 (PML4 slot 424; in use: 256 the HHDM, 384 the smoke test page, 416 heap, 418 the stack arena, 420 the shared window, 422 the device/firmware windows, 511 the kernel image), with a const assert in the style of apic.rs:31-33 that it overlaps none of them, and a `kva_reserved()` refusal added to `map_kernel_page` and `unmap_page` beside `heap_reserved` (paging.rs:609-614, :675-680). Its table hierarchy is pinned at init (the prepare_heap_window pattern, paging.rs:332-358), before `share_with_secondaries` (paging.rs:329-341): 18 pinned frames for 32 MiB (a PDPT, a PD and 16 leaf PTs). The VA allocator's state is a static bitmap (8192 pages, 1 KiB of .bss — never the heap, so `capacity_self_test`'s used==0 holds, heap.rs:593). Sizing: 256 guarded stacks need 18 MiB with their guard gaps (72 KiB of VA each); the rest is reserve, and Phase 2 object storage is heap v2's arena, not this window. Mapping and pooling rules: absent-to-present maps are always local, in every mode — TLBs and paging-structure caches hold only present entries, so a fresh mapping needs no remote invalidation (and a cancelled AP, smp.rs:259-266, changes nothing). Unmaps happen only to trim the reuse pool, in batches (MAX_INVALIDATE_PAGES = 256, smp.rs:44), and only when `prepare_kernel_update` succeeds (smp.rs:785-814); after publication the shootdown stays fail-stop, as today (smp.rs:828). When the transport is unavailable the pool simply stays mapped — nothing is ever quarantined, and a degraded boot reports itself once in every flavor with a content-free line in the style of MIRROR_SHARED_VM_SKIPPED (kernel_vm.rs:126). `invalidation_range_valid` (smp.rs:636-658) whitelists the window. On a 1-CPU boot, where the seal is never set (smp.rs:400-406), the window works through the same API. Rejected alternative: extend the shared window (single-page, 2 MiB, paging.rs:241-303). | proposed |
| 0050-D4 | Markers. `MIRROR_KVA_READY base=0xffffd40000000000 size=33554432` prints once per boot in every flavor right after the window is prepared — before `share_with_secondaries`, so before the SMP line — and `MIRROR_CPU_DATA_READY cpus=<n>` prints after SMP bring-up; both join test.ps1's default and trace `$required` lists (test.ps1:35-40), and common.ps1 checks each exactly once with its full field list in that order, recomputing cpus= from MIRROR_SMP_READY online= (the MIRROR_SMP_READY pattern, run.ps1:78-80, common.ps1:402-437). `MIRROR_KSTACK_OK threads=<n> watermark_pages=<n> pool=<n>` is boot-smoke only, prints once per init-pair session (twice per smoke boot) after its thread battery: threads= is the session's peak live thread-stack count (16), 1 <= watermark_pages <= 16, and pool= is the reuse pool's size at drain (0 quarantined in every normal scenario — there is no quarantine path). It joins both `$forbidden` lists (test.ps1:36, :40) and capture.ps1's absent list (capture.ps1:695-698). `MIRROR_KSTACK_GUARD guard=<hex>` is boot-smoke only, printed only by the ThreadStackOverflow fault case (test 3) and rejected in every other scenario, and joins both `$forbidden` lists. | proposed |

## Interfaces
- `kernel/src/cpudata.rs` (new): `CpuData`, the static table, boot/AP install, `current_cpu()`.
- `kernel/src/kernel_va.rs` (new): the D3 window allocator, the static bitmap, the reuse pool and the trim path.
- `kernel/src/interrupts.S`, `kernel/src/userspace_entry.S`, `kernel/src/interrupts.rs`: the D1 state machine (entry/exit/paranoid-IST/suspend paths and their FS handling), the self-test rewrite, per-dispatch RSP0, `MIRROR_USER_KERNEL_RSP` moves into `CpuData`.
- `kernel/src/smp.rs`: the AP install point (:493-495, before the readback at interrupts.rs:613), a new boot-smoke IPI operation (OP_READ_CPU_DATA) in `operation_valid` (:671-685) and `handle_ipi` (:919-997) for acceptance 2, and the invalidation whitelist (:636-658).
- `kernel/src/sched.rs` (0030a): the create continuation (0050's own, on 0030-D2's completion pass), the exit/teardown frees into the pool, and per-dispatch RSP0.
- `kernel/src/paging.rs`: the third prepared window and the `kva_reserved` refusals.
- `kernel/src/boot.rs` and `kernel/src/main.rs`: the `thread-stack-overflow` token beside the existing modes (boot.rs:176-189) and its arm in main.rs's smoke_mode match (:444-500); the BSP's CpuData install between interrupts::init and tls_ready (main.rs:60-63).
- Scripts: run.ps1 gains `-Fault ThreadStackOverflow` (ValidateSet :25, $testMode :288, $fatalKernelFault :511, the $vector map :898, and the cr2 check against MIRROR_KSTACK_GUARD, the :928 pattern); test.ps1 adds the case in both profiles and the image-list changes of D4; capture.ps1's absent list gains MIRROR_KSTACK_OK and MIRROR_KSTACK_GUARD; common.ps1 gains the exact-once checks.
- readme.md: :7 (thread stacks), :201 (the INT3 test's "cleared state" becomes the CpuData invariant, with the sentinels in IA32_KERNEL_GS_BASE), :219 and :305 (the BSP RSP0 stack as the placeholder; ThreadStackOverflow is the live test), :241 ("User entries use TSS.RSP0 and a dedicated guarded 64 KiB kernel stack" becomes per-thread stacks), :497 (THREAD_CREATE's -11 row gains stack-allocation failure) and :560 ("Kernel execution clears the user bases" becomes the D1 state machine). AGENTS.md's fault-injection steps gain the case under their existing rules.

## Acceptance tests
1. The existing battery passes on the new entry path: threads, sync, TLS (a user non-null GS selector and base survive a syscall, a preemption and a suspend), FPU, paging and scheduler checks, with `MIRROR_TLS_READY`/`MIRROR_TLS_KERNEL_OK` asserting the D1 invariants.
2. Per-CPU data: OP_READ_CPU_DATA proves on the BSP and every online AP that GS resolves to that CPU's `CpuData`, matching its `SLOTS` entry; `MIRROR_CPU_DATA_READY cpus=` equals the recomputed online count. A boot-smoke probe sets IA32_KERNEL_GS_BASE = CpuData and IA32_GS_BASE = a user-range value (the exit-window state), runs `int 2`, and checks that the handler saw this CPU's `CpuData` and that both MSRs are restored on return; the IST probe (MIRROR_IST_OK) is also run with a nonzero user-style GS base installed at CPL0.
3. Thread stacks: two threads interleaving syscalls trap onto distinct stacks (entry RSP readback inside each thread's guarded range, boot-smoke only). `-Fault ThreadStackOverflow` (`mirror.test=thread-stack-overflow`) allocates a stack through the D3 path, prints `MIRROR_KSTACK_GUARD guard=<hex>` then `MIRROR_TEST_EXPECT_FATAL vector=8`, walks the stack downward as overflow_rsp0 does, and faults with cr2 in the reported guard page, exiting 35 (the run.ps1:904/:928 checks follow). run.ps1 rejects MIRROR_KSTACK_GUARD in every other scenario; test.ps1 runs the case in both profiles.
4. VA allocator: a boot-smoke self-test allocates, maps, probes on every CPU (the heap.rs:304-311 pattern), frees into the pool, reuses, and trims, with guard gaps intact and exact frame and window baselines. Degraded mode runs through a boot-smoke switch that makes the window code see an unavailable transport for one session without failing an AP: thread creation still works through local mapping and pool reuse, the trim is skipped, and the boot reports the degraded line once.
5. Stack-failure injection, armed inside the battery (the heap GrowthMode pattern, heap.rs:262, :280): the Nth stack frame during SYS_THREAD_CREATE and during process creation fails; both fail with -11 (or the launch failure path) and restore the exact frame and window baselines.
6. Capacity: with 0030a, 256 threads across 64 processes each get a stack (the window's 18 MiB); creation beyond that fails EAGAIN with rollback, and the session-drain baselines hold with the pool at its expected size.
7. Before merge (P8): the full `scripts/test.ps1` in debug and release, plus `test.ps1 -AgentDemo` while the agent-demo feature exists (RS6). All script changes land in the same commit.

## Open questions
1. The thread-stack size: 64 KiB is proven; 32 KiB halves the 16 MiB full-capacity frame cost if the watermark allows. Decided after test 3's first measurements; the spec keeps 64 KiB until then.
2. The window size (32 MiB: 18 MiB of stacks plus reserve, 18 pinned page-table frames): confirm or adjust.
3. RD21 must be confirmed together with 0050: it removes docs/specs/README.md:38's SYSCALL-rework clause from this scope and retires decisions.md:213's inferred placement. If it is not confirmed, this spec still builds no SYSCALL entry (EFER.SCE stays off); 0021 then adopts D1's GS discipline unchanged when it is written.
4. 0050 is built only after 0030a is confirmed (RD24) and its review findings are resolved; D3's sizing and test 6 follow 0030a's confirmed capacities rather than literals.
