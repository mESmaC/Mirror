## Goal

Provide the testable Rust controllers, package provenance, bounded operations, durable recovery records and shared machine leases for an opt-in headless check lane. [0015d](0015d-vmware-cases.md) supplies the actual VMware adapters, profile, guest oracles and cases. Functional results are not performance measurements.

The dependency order is **0015c host work → separately authorized D10/D11 provisioning and investigation → 0015d VMware implementation/acceptance**. Host tests use fake VM adapters; they do not prove VMware completion or recovery. Package recovery is usable after its own host acceptance. Actual VM cases and VM recovery remain disabled together until 0015d proves D11, even if the host library has merged.

## Interfaces

### Entry, sources and implementation boundary

Entry: `scripts/vmrun.ps1 -Vmx <path> -LaneRoot <path> -LockOwner <nick/task> -Case boot|suspend-resume|restart`. Recovery uses `-Recover <run-id> [-PowerOff]` instead of `-Case`, resolves VMX from the canonical LaneRoot record and rejects a conflicting supplied VMX. Package recovery is `scripts/package.ps1 -Lane -Recover <package-id> -LaneRoot <path> -LockOwner <nick/task>`; it never needs a VMX or performs power actions. New cases never adopt an unreleased lock. Optional `-Vmrun <path>` overrides discovery through the 64-bit VMware Workstation `InstallPath` registry value. Use argument arrays and hidden processes; no credentials, implicit `all`, build or repackaging.

The Rust lane owns deadlines, transitions, oracles, journals and evidence behind injectable command, clock, serial, state/listener and artifact adapters. The host spec also puts the lane-package controller in Rust; `package.ps1 -Lane [-Release] -LaneRoot <path> -LockOwner <nick/task>` is its thin entry. Thus the cargo host tests exercise production controllers with fake command runners and temporary files, without Pester or a second orchestration implementation.

Host implementation scope: the reusable controllers/adapters in `tools/perf-probe`, thin `scripts/package.ps1` lane entry and disabled VMware entry in `scripts/vmrun.ps1`, host checks in `scripts/test.ps1`, and matching AGENTS/P9 and team recovery documentation. Document released-owner publication as the first release step, identity-checked move aside, detached leftovers and named replacement recovery. 0015d owns the live VMware adapters/entry activation, profile and vm-settings corrections. No kernel/userspace changes, `common.ps1` retrofit or other script lock edits.

### Packaging and fixed VM binding

Lane packaging acquires/releases the machine lock independently of the later VM case and never changes VM staging. Resolve one clean committed tree and export it with `git archive` under `<LaneRoot>/packages/<package-id>/source`, outside every checkout, with fresh output directories. Only this controller writes the scratch tree; cooperating agents never edit it. Inventory hashes before/after detect persistent changes; they do not prevent transient tampering by another process. Stronger isolation would require a re-confirmed change to D9 plus sealing, unsealing and crash cleanup in the host spec.

Cargo searches ancestors and Cargo home as well as the project ([configuration hierarchy](https://doc.rust-lang.org/cargo/reference/config.html#hierarchical-structure)). Reject `.cargo/config` and `.cargo/config.toml` in every ancestor above the export through the volume root. Resolve and record the operator's existing cached `CARGO_HOME`; reject its `config` and `config.toml`, preserve the exported project's configuration, and set `CARGO_NET_OFFLINE=true` with locked resolution ([environment variables](https://doc.rust-lang.org/cargo/reference/environment-variables.html)). This uses Cargo's own cache handling, not copied internal layouts; missing cached inputs fail. Clear/reject inherited source, compiler, flags and output overrides against a recorded allowlist. Verify the pinned toolchain, and copy the verified cached Limine archive into the export's private `.tools`; no shared extraction junction or download.

Build default flavor without agent-demo/perf tokens. Copy the private build's image/descriptor to the calling checkout's `build/dist`; publish `mirror.package.json` there last and atomically: schema, package-id, source commit/tree, clean status, profile/features/toolchain, committed-source inventory, capability/oracle versions and image/descriptor sizes/SHA-256. Inventory only committed source files, excluding generated `build`, `target`, `.tools` and lane artifacts. All packaging modes invalidate an old record before replacing files; only `-Lane` publishes one. Partial/mixed generations fail. The host spec requires merged main code tips `14cb7b2` (0017b) and `3c87bcb` (0017c) as ancestors of the package commit; restart also requires the later confirmed, merged 0058a capability commit. Historical pre-rebase IDs, the later checkout HEAD and staged ELF are not provenance.

Before exporting, journal the package-id, operator, original checkout, canonical scratch/output paths, controller PID/start time and child-job identity under `<LaneRoot>/packages/<package-id>`. All Git/archive/build/PowerShell/Cargo/linker/mirror-image children and descendants belong to a separate kill-on-close job, with no breakaway or inherited controlling handle. Record each directly created worker's PID/start time while it is still suspended in that job, durably before allowing execution. The controller's death ends its build tree; the adapter must demonstrate this in host tests before packaging is enabled. After verified publication, scratch cleanup and proof of no live build, persist that package's `final.json` as `finalized-valid` before release. Lane staging requires this valid LaneRoot record as well as the matching published manifest/hashes; an incomplete or recovered-invalid record cannot be bypassed by a leftover manifest.

The controller's `finally` removes only its canonically verified scratch directory, with no reparse traversal, retaining logs/manifests outside it. After a crash, the recorded operator runs package Recover from its own checkout, obtains the lease under D6 and checks the recorded controller/worker identities and job membership. No scratch cleanup or release until the old controller has exited and its job has no live descendants; missing evidence or a live process leaves the operation blocked, never delete by age. Recover never resumes a build or publishes a partial package. For an incomplete operation it records a failed/recovered verdict and invalid generation in `<LaneRoot>/packages/<package-id>/final.json`; an already durable `finalized-valid` verdict is preserved after rechecking its hashes and no-live-build proof. It removes only any remaining verified scratch tree, then releases the machine lock using the shared release procedure. If scratch deletion is denied, preserve its exact path and an `abandoned-artifacts` failure record; after proving no live build it may still release the lock, and future packages use new identities/paths. It never writes to another checkout. Use the same named-replacement rules as VM Recover. On the normal path, denied scratch deletion likewise records a failed/invalid package and the exact abandoned-artifacts path; it cannot become finalized-valid. After no-live-build proof the controller may release. A previously durable finalized-valid record recovered later keeps the hash/proof revalidation rule above. There are no ACL seals to undo.

Provisioning records one canonical VMX-to-LaneRoot binding. Preflight requires resolved `sata0:0.fileName` = `<LaneRoot>/disk/mirror.vmdk`, its adjacent extent `mirror.img`, and `serial0.fileName` = `<LaneRoot>/serial.log`. Reject LaneRoot inside any Git worktree, beneath Cameron's `C:\Users\engin\Desktop\Mirror`, or through reparse aliases. Compare canonical Windows path components, not string prefixes: `Mirror-vm` is not beneath `Mirror`. The root must match the binding; another root cannot bypass its journal. No snapshots/parent chain or extra disk. With proven off state and lock held, stage the **calling checkout's `build/dist` image/descriptor and `mirror.package.json`** through hash-verified temporaries and publish a generation last. After off, compare both hashes exactly; preserve and fail on mutation.

The binding and staging checks are host contracts exercised with fake state/artifact adapters in this spec. Actual provisioning, VMX profile validation and off-state proof belong to 0015d. Generic record limits are 1 MiB for VMX, 256 KiB for manifests/journals and 16 KiB for owner records; lane-generated records have versioned schemas.

### Operation and transport bounds

All operation deadlines are monotonic totals, capped by remaining case time; progress never resets them.

| Operation | Cap |
| --- | --- |
| Active case including staging | 900 s; busy lock fails immediately. |
| Package validation/staging; state/listener phase | 120 s; 15 s, at most 32 queries. |
| Lifecycle command; guest readiness | 60 s; 120 s. RFB connect attempt ≤3 s. |
| Typed action including frames | 30 s, ≤32 pairs/action, ≤64/case; immediate ≤200 ms down/up contract in 0015d. |
| Failure release/evidence, stop, off verification | 30 s + 60 s + 15 s = 105 s maximum after active case. |
| Recover; Recover -PowerOff | 120 s without power actions; 300 s with explicit PowerOff (≤60 s prior-intent reconciliation, three 15 s state phases, two 60 s lifecycle actions, 30 s evidence = 255 s). |
| Package Recover; D11 interrupted-command observation | 120 s total; 120 s per injection respectively. D11 is a separate investigation with confirmed scope, outside case caps. |

Suspend-resume uses 37 key pairs, the longest case; allow one emergency key-up. Keep one RFB request outstanding across timeout, invalidate coverage/geometry on resize and require complete frames. Readiness polling may request non-incremental full frames when no request is pending. Cap connection attempts at eight/case, ≤3 s each within the case deadline. This is not a reconnect-per-checkpoint policy. Review the WIP primitives' caps of 4096 pixels/dimension, 4096 rectangles/update, 128 MiB/message and 1 MiB/string; malformed input fails.

The case sequences, immediate down/up contract, setup priming and exact checkpoint meanings are owned by [0015d](0015d-vmware-cases.md#pixel-and-input-contract). These bounds also constrain its adapters; D11's per-injection observation is distinct from a reported case.

### Acquire-only lock and same-run recovery

New lane/package invocations atomically create the team directory, retain the four readable owner fields plus `lane_schema=1`/`lane_kind=vm|package`/`lane_run=<id>` and a fresh lease identifier, and hold an exclusive write/delete-excluding handle on `owner.txt` throughout execution/finalization. An unreleased directory is busy for new work, including the same nick/task. An owner's final valid `released=<UTC time>` line makes its generation free under the team protocol, whether it is a manual or lane record. A new case or either Recover may detach that released generation using the procedure below and atomically create a fresh lease; it never erases the release line or reuses the old lease. Detachment targets the verified directory identity, not merely the reusable pathname, and cannot rename or delete a successor after a race. Failure to detach/acquire within the state-phase cap returns busy with evidence, even though the old record is released. No age/PID-based takeover or rewriting an unreleased foreign record.

Before staging, durably journal `preparing` under LaneRoot with operator/run, original worktree (provenance only), bound VMX/root, paths and last proven state. Record each power intent and dispatch time before dispatch, including restart Enter; partial staging is invalid. On error, release keys and preserve the first failure. A positively running VM may receive one cleanup stop only after previous power intents are reconciled.

One long-lived Rust controller owns the lease and every vmrun child. Assign each child before execution to a Windows [kill-on-close job](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) whose sole controlling handle belongs to the controller; disallow breakaway. Journal the controller/job identity and every directly created worker's PID/start time while suspended, before allowing execution; descendant membership must remain in that job. D11 must verify that all command workers are covered while VMware's service/vmware-vmx remain outside the job. Timeout/cancellation kills command workers, never vmware-vmx. If this separation cannot be demonstrated, guest cases and controller recovery stay disabled together; D11 is performed manually by the owner under today's team rules.

For an unresolved prior intent, reconciliation first establishes that its command job has no live workers/descendants, checking PID plus start time rather than PID alone; after a controller restart, also prove the prior recorded controller has exited. The current controller remains alive and holds the lease during its own cleanup. It then waits out the 60 s intent budget (a full 60 s if elapsed time cannot be trusted across restart) and reads D11's verified completion/state indicators twice within the state-phase cap. **Time and matching snapshots are not proof by themselves:** D11 must identify a terminal completion/cancellation rule that also excludes later work accepted by VMware's service. Validate it by killing start/stop/suspend workers before dispatch, after dispatch/acknowledgment and during transition; after the claimed terminal state, observe for 120 s with at most 240 polls and require no late VM process, new vmware.log session or state change. The mechanism evidence and all injection traces are prerequisites; a quiet observation window alone cannot pass. Until this rule succeeds, treat the VM as transitioning even when off/suspended is observed. The owner retains the lock and posts evidence in chat; it may rerun Recover after the intent budget, but elapsed time never authorizes a repeat power action. Cameron decides any other action. Apply the rule to failures and every recovery path.

Codex runs recovery from its own current checkout using the canonical LaneRoot record; it never needs the original worktree. `-Recover <run-id>` verifies the recorded operator/run and binding, obtains the exclusive handle on its retained **unreleased** lane lock, or atomically acquires a fresh lease when the directory is absent or validly released as above. A released lease is never taken back, even for the same run. Concurrent/active holders fail. Missing or mismatched run identity blocks, rather than borrowing another lock. Plain Recover only reconciles and finalizes a proven-off run, or journals proven suspension and releases; running/unknown states remain locked with instructions to invoke PowerOff. Partial/absent staged files are evidence, never repaired silently.

Explicit **`-Recover <run-id> -PowerOff`** holds that same lease in one process through reconciliation, power actions and finalization. Once state is known: off needs no action; running gets `vmrun -T ws stop <bound-vmx> hard` once; suspended first copies the complete current serial epoch into durable run evidence, then gets `start <bound-vmx> nogui` once and, after proven running/completion, `stop <bound-vmx> hard` once. Failed serial preservation prevents start because VMware may replace the file. Journal each action, prove off, preserve the failed run's verdict, then finalize/release. No repeat of an ambiguous action, reset, `.lck` deletion or separate shell handoff. D11 must verify both paths and interrupted-command reconciliation before guest cases and recovery are enabled together; otherwise guest cases stay blocked, with evidence for Cameron.

If the recorded operator is unavailable, follow the team's stale-lock rule and ask in chat. Only Cameron's explicit authorization naming the run/root, original operator, replacement operator and recovery scope permits replacement. After verifying that run and obtaining its exclusive lease, append the authorization text/reference and both identities to LaneRoot and append the replacement's nick/authorization reference to `owner.txt` before acting. Preserve the original ownership history; the current holder is explicit. Never impersonate the old operator or write its worktree. The separately confirmed VMR-D6 exception requires team-rule documentation before use; it does not permit general adoption. No authorization means no takeover.

Release the lane-created directory only at these points: packaging ended with no live build; durable `finalized-off` (pass or fail); a reconciled suspended failure; or those same off/suspended outcomes in Recover. Suspended release first preserves `suspended-needs-recovery`; its journal prevents restaging/new cases. Running, unknown or unresolved states retain the lock; planned successful suspend/resume retains it across the dwell. Release must preserve run identity and cannot remove a successor's lock.

Use one release procedure for normal completion and both recovery modes. Persist the eligible final state and release intent first. Through the still-held owner handle append the lane run/lease identity and the owner's final `released=<UTC time>` line and flush it; record `lock_release=owner-record` with that identity/time in the run journal and `final.json` before closing the handle. The operator posts `lock released`. Never delete contents at the shared acquisition pathname. If permitted, atomically rename the verified released directory generation to a unique non-existing sibling `qemu.released.<unique-id>`, using directory identity and no-replace semantics so a competing taker cannot redirect the operation to a successor. Only after that detachment may optional deletion remove contents at the verified sibling path; record `lock_release=detached` with the sibling identity/path, then `removed` if cleanup completes. A new taker uses this same detach-first procedure for a released record, then atomically creates its fresh `qemu` lease. Rename denial leaves the released owner record intact for a later taker; deletion denial after detachment leaves only a reported cleanup artifact, which cannot block acquisition. The detaching operator owns later cleanup of that recorded sibling, after posting its exact identity/path in chat and re-verifying it; it holds no machine lease. This never permits touching a new acquisition directory. A crash between deleting the detached owner file and its directory therefore cannot create an ownerless directory at the shared acquisition pathname. A crash before the release record is durable requires Recover; a crash after it never authorizes retaking the old lease. A lagging journal field is reconciled against the owner record or proof that a successor/absence replaced that generation, without changing the VM verdict.

### Evidence and finalization

Full evidence may live in the operator's current `build/vm-logs/lane/<run-id>`: source/package/staging hashes, settings, tool/oracle/policy versions, steps/deadlines and final cleanup state. Preserve serial epochs before replacement; truncation/missing lines/unprovable boundaries fail. Revalidate after off. Before release, atomically persist `<LaneRoot>/runs/<run-id>/final.json` containing verdict/first failure, capability/package/staging hashes, VM binding, reconciled intents, off proof and evidence locations/hashes; the root journal points to it as `finalized-off`. All recovery-critical state lives in LaneRoot. Later cases read only this durable record plus fresh off proof, never a prior worktree. Deleted bulk evidence is reported as unavailable without discarding the retained verdict/proof. Missing final records remain incomplete and require Recover.

Checkpoint counts: boot four (shell, console, status edit/result); suspend nine (adds echo edit/result, retained history, new status pair); restart nine (adds restart edit, new shell/console, new status pair). Cap 12 normal plus four failure frames; do not save every poll. Cap command streams at 1 MiB each/16 MiB total, serial and VMware logs at 64 MiB each across generations. Overflow preserves the bounded prefix/reason and fails. Cleanup success never replaces the first failure. Label synthetic fixtures separately from VMware captures.
