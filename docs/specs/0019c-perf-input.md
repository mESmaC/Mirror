# 0019c: Finite perf input capture

Status: draft. Every decision below is proposed; implementation and VM runs require Cameron's confirmation.
Depends on: confirmed and implemented 0019a, merged 0017a/b/c; before 0030a. The Phase 1 exit additionally requires 0018's host probe and 0019d/0051/0052's load work.
Ledger: S7/S7a/S7b, S10, G7/G7a, G11; proposed RD8 and 0019-D16's amendments to 0018.

## Goal

Collect bounded input-to-next-physical-tile diagnostics without printing perf lines during collection. Make the host's visible-response measurement an explicit prerequisite for the Phase 1 exit.

## Non-goals

No input ABI change, complete-frame/causality claim, scheduler policy, burn implementation, flip calibration, AP clock implementation or other-OS work. A first tile after input delivery can be unrelated to the requested response.

## Decisions

| ID | Decision, reason and alternative | Status |
| --- | --- | --- |
| 0019-D7 | Recommend finite capture with internal event identities, then seal and drain outside measured work. Quota sealing stays quiet until the host finishes and exits the session. Idle-only draining has no guarantee after scheduler changes; immediate serial perturbs the measurement. The kernel endpoint is a diagnostic proxy only. | proposed |
| 0019-D17 | Recommend 200 keys, 256 input records, 40 buffered MEM samples, 60 s setup, 330 s collection and 30 s post-quota finish, with the host bounds below. At 1.5 s per key, 200 keys need at most 300 s; collection has 30 s margin and excludes setup. Alternative: fewer keys in a shorter window, with correspondingly weaker distribution reports. | proposed |
| 0019-D18 | Recommend raw host RFB-to-pixel p99 <30 ms on the proposed G11-size Phase 1 VM below, using 0018-D10's `tools/perf-probe`. This deliberately strengthens the old guest-proxy bound: 30 ms now includes VMware input delivery, framebuffer coalescing and VNC display cadence. That overhead may consume most of the budget; feasibility is unproven. Alternatives: set a host bound after `perf-probe calibrate` and O3 baselines, deferring the gate until those land; or retain a kernel-proxy <30 ms gate and report host latency without a visible-response claim. Cameron must confirm the oracle and bound together; none is already a Phase 1 requirement. | proposed |

## Interfaces

### Collection and identity

`mirror.perf=1` enables capture only with HPET and the interactive physical Input/surface owner selected by 0019a. Smoke and no-clock behavior retain 0019a's skip rules. Setup expires 60 HPET seconds after `shell_ready`. Before arming, clicks only update pointer state. Admit an arming key only before setup expires. Its first byte must be at or after `shell_ready` and, with burn, at or after burn dispatch. Its first-byte timestamp is WINDOW start; collection ends at start plus 330 seconds. Checked arithmetic rejects overflow. No rearming occurs this boot.

Discard partial events whose first byte predates arming, while preserving the pointer baseline. Accept the first 200 key makes, including autorepeat, and intervening button **presses**: one record when any supported button changes from up to down. Releases, motion, ACKs, errors and unknown sequences create no record. After loss, the first fresh pointer state establishes a baseline without fabricating a press. Untimed close-control presses are still records once armed.

Origins remain separate in every report:

| Origin | Start observation |
| --- | --- |
| 1 | Keyboard first byte drained in IRQ context |
| 2 | Relative pointer packet's first byte drained in IRQ context |
| 3 | Vmmouse DATA read producing a press during an IRQ drain |
| 4 | Keyboard first byte drained by polling |
| 5 | Relative pointer first byte drained by polling |
| 6 | Vmmouse DATA read producing a press during deferred/polled draining |

For PS/2, carry the first-byte timestamp and context through prefixes/packets. AUX routing identifies the device; the IRQ vector alone does not. A vmmouse doorbell is not the press. Snapshot each qualifying DATA read rather than borrowing its doorbell's time. Mixed prefix/packet contexts keep the first byte's origin. Do not pool IRQ and polled/deferred distributions.

Give each admitted event sequence 1..256. Carry bounded sidecars through decoder queues and Input Session pending/retry without changing the 32-byte user event. Delivery occurs only after successful copyout **and consumption** by the physical Input owner. Failed/retried receives cannot deliver twice. A successful positive physical present pairs all delivered, unpaired records with its completion snapshot; offscreen app presents, failed/empty presents and undelivered events do not qualify.

Count overlap when admitting a record while another remains unpaired. Preserve the original press identity across same-button coalescing, or cancel it explicitly; never replace it with a newer event's identity. Queue loss, fallback and discard cancel affected identities. Cancellation leaves their records unpaired, increments loss and requests abort sealing (reason 5); later input cannot repair the run. No per-event allocation or perf printing occurs while collecting.

### Sealing, memory and output

Seal after 200 keys when every admitted record is paired, at the active deadline, on session exit/abort, or when admission would exceed capacity. Setup expiry seals an unarmed window with reason 6; collection expiry uses reason 2. Producers reject new records, pairings and buffered MEM at or after the collection deadline. Scheduler return/idle passes finalize sealing; this is not a hard real-time completion guarantee. Fatal/stopped guests produce incomplete runs.

Expose the same kernel-only state to every caller, including 0019d: immutable seal `{armed, start, end, reason}`, `finish=<not_waiting|awaiting_exit|timely_exit|failed>`, and `drain_complete`. Quota seal sets awaiting_exit; other seals set not_waiting. A timely normal exit sets timely_exit, and timeout or abnormal completion sets failed. An abort request may seal before cleanup but cannot rewrite an existing seal. Retain records and the drain cursor outside process-owned state through teardown; no old identity may leak into a new session.

Initial and pre-arming MEM emits normally. During collection, buffer 0019a's 10-second samples separately: at most 34 in 330 seconds, capacity 40. Buffer exhaustion increments overflow and seals with reason 4. Every seal freezes pending records as unpaired, without itself incrementing loss, and pauses MEM sampling. No later input changes the frozen window.

After quota seal, hold all perf output and keep 0019d's load active until the host observes final response pixels and sends ordinary Escape. Normal session exit must occur within 30 seconds of seal, with or without burn; this Escape creates no new record. Enforce the deadline before dispatch and on scheduler returns, so delayed handling cannot count a late exit as timely. The kernel sees exit, not pixels: the host supplies pixel evidence and rejects absent or late cleanup independently of the frozen WINDOW. Timeout or abnormal completion sets finish=failed and burn completed=0.

Drain in this exact family order: INPUT by sequence, buffered MEM by sample order, one WINDOW, then BURN if a launch was attempted. At most 256 + 40 + 2 lines are retained; initial/pre-arming MEM and lifecycle output are separate, already-emitted lines. For a seal whose session continues (setup expiry, collection deadline, capacity, loss or finish timeout), first stop and reclaim burn if present; then emit at most four retained lines on each scheduler pass, outside IRQ, decoder and present handlers. After the complete drain, a still-live session resumes ordinary MEM without catch-up. No live drain runs while finish=awaiting_exit.

When a session exits, drain all remaining retained lines once in its teardown; no further scheduler pass is required. In run_shell: seal if needed, stop/reclaim burn, close all other children with SessionEnded, release shell handles/address space and verify reclamation, then drain before MIRROR_SHELL_CLEANUP_OK. Burn's RECLAIMED/CLOSED and Notes' SessionEnded RECLAIMED/CLOSED therefore precede the teardown drain; WINDOW precedes BURN; both precede shell cleanup and the later MIRROR_CONSOLE_READY. For Click, Notes' explicit-close lines occurred during collection and still precede the drain. In run_desktop, finalize and drain after both processes' resources are reclaimed but before MIRROR_DESKTOP_CLEANUP_OK and MIRROR_AGENT_CLEANUP_OK. If a live drain was partly emitted, teardown consumes only its remaining suffix. Set drain_complete exactly once. No MEM sampling or perf drain resumes in the later kernel console.

Exact field order, using decimal u64 values or `none` and no user content:

```
MIRROR_PERF_INPUT seq= origin= start_ns= present_ns=
MIRROR_PERF_WINDOW start_ns= end_ns= keys= buttons= records= paired= overlap= loss= overflow= unpaired= reason=
```

Unpaired `present_ns` is `none`. Reasons are 1=quota, 2=collection deadline, 3=normal session exit, 4=capacity, 5=abort/loss or abnormal exit, 6=setup expiry. Unarmed start is `none`, with zero keys/buttons/records. End is the logical seal/deadline timestamp, not the later drain time. Each armed record satisfies `WINDOW start <= start <= present <= WINDOW end`, omitting present when unpaired. Completed-event admission determines sequence; first-byte starts may reorder across devices. MEM timestamps are nondecreasing. Require `records=keys+buttons=paired+unpaired`, exact sequence coverage, and origin-derived key/button counts. Strict 200-key diagnostics require quota completion and zero overlap/loss/overflow/unpaired. Exit and Click require reason=3 and loss=overflow=0. Truncated/malformed serial invalidates the run.

### Host checks and visible response

Extend 0019a's proposed `capture.ps1 -PerfCapture -Perf <items>` default-flavor mode with `-PerfScenario Markers|Keys|Click|RelativeClick|Overlap|Deadline|Exit`. Input scenarios exclude AgentDemo; Markers retains 0019a's rules. PerfCapture excludes Hygiene. SMBIOS delivery and the -NoHpet switch belong to 0019a. Preserve trace captures and their budgets. RelativeClick requires -RelativePointer. Burn is accepted only with Keys or Exit, or with Markers when AgentDemo or NoHpet guarantees a skip; reject burn with Click, RelativeClick, Overlap, Deadline and ordinary HPET Markers before building. No skipped burn attempt can create a child.

Keys opens/focuses Notes before arming, parks the pointer outside the probe, and alternates `a`/Backspace for 200 keys. Every next key waits for the preceding expected text pixels and then 250 ms. Key down, release, pixel confirmation and gap together have a 1.5-second bound; release immediately after down, within 200 ms even on errors. A timeout fails the capture without injecting another measured key. After the final confirmed response, send Escape immediately. Both Escape and successful shell cleanup must occur within 30 host-QPC seconds of the final measured key-down, which precedes quota seal; do not start that host deadline at the later pixel observation. This conservative check applies even without BURN and rejects late completion hidden by a frozen WINDOW. These bounds allow throttle stalls without typematic repeats. Full runs have a 480-second outer timeout, including setup and drain. Raise capture's accepted maximum from 300 to 600 seconds; this does not extend guest deadlines or the ordinary default timeout.

QEMU uses QMP input and expected screenshot rectangles as functional assertions, never gate timings. The 0019c implementer owns `perf-probe input --protocol phase1-keys` in the existing std-only 0018 workspace and its synthetic protocol tests; no second RFB client is added. The mode follows the Keys protocol above: one session, exactly 200 keys, no warmups, immediate key-up within 200 ms, expected response pixels followed by a 250 ms gap, and final Escape. Existing `input` without this option keeps 0018's 20 warmups, 200 measured keys, three sessions, random gaps and no Escape. Add this interface amendment to 0018 through D16 before implementation; incomplete 0018 work stays deferred except for an explicitly assigned host-probe handoff.

Host QPC starts at key-down write and ends at the first matching response pixels. Mask pointer and irrelevant pixels; record rectangles and tolerance. Keep one pending incremental request. Timeout releases input and invalidates the run; any reconnect performs cleanup only, never resumes samples. Report raw latency with no flip subtraction. Nearest-rank p99 is the 198th sorted sample of exactly 200 successes; any timeout invalidates the gate. Only release VMware runs on the profile below can qualify under D18. Report VMware's display cadence separately: 0018 records up to 10 ms framebuffer coalescing and remote display polling/compositing intervals, so <30 ms is a new proposed host-path bound, not the old guest bound. Kernel timestamps cannot replace a missing host frame.

The proposed measurement binding is a dedicated VM named **Mirror-Phase1**, not an assumed existing Documents VM or 0018's 4-vCPU/8-GiB baseline. It uses G11's 12 vCPUs, 20 GiB and NAT: `numvcpus="12"`, `cpuid.coresPerSocket="12"`, `memsize="20480"`, `ethernet0.connectionType="nat"`. Inherit docs/vm-settings.md's Workstation-created HW22, other-64/EFI/Secure Boot off, SATA/e1000, no USB, HPET and default 3D settings. Set `monitor_control.restrict_backdoor="TRUE"` under 0017-D19; its acceptance under ULM is not a CPL3 enforcement test. Boot only the task worktree's release default image from `package.ps1 -Release -Perf 1,burn`, at `build/dist/perf/mirror.vmdk`; require its recorded kernel/module hashes and actual 1920x1080 GOP mode. No vTPM, encryption or snapshot baseline is added to this Phase 1 binding. The definitive profile and absolute VMX path must be recorded under docs/vm-settings.md through Claude's RD16 handoff before any qualifying run. G11-size configuration does not authorize creating or operating the VM now.

For this VM, add 0018's measured transport explicitly: `RemoteDisplay.vnc.enabled="TRUE"`, `RemoteDisplay.vnc.ip="127.0.0.1"`, fixed port `5901`, no password/key, keyMap unset (US). Prove that port is free before start and loopback-only afterward. Keep VMware's RemoteDisplay cadence keys at their defaults. Serial uses `serial0.present="TRUE"`, `serial0.fileType="pipe"`, `serial0.fileName="\\.\pipe\Mirror-Phase1-perf"`, `serial0.pipe.endPoint="server"`, with perf-probe as client and continuous QPC-stamped reading. Before measurements, perform 0018's pipe-versus-file first-line check; if bytes are lost or delayed, use its documented endpoint=client/precreated-host-pipe fallback and record that profile. Require complete ordered perf/device readiness, absolute vmmouse, expected rendered shell pixels, 1920x1080 RFB ServerInit and unchanged size. Apply 0018's static-frame fidelity and idle-probe sanity checks and record raw-frame cadence, VMX hash, VMware build, ULM monitor line and host preparation. A failed transport/fidelity check blocks the gate. The loaded Phase 1 exit also waits for 0019d, 0051 and 0052; early BSP-only runs are labeled diagnostics.

For VMware/RFB input scenarios, after absolute vmmouse and rendered shell readiness, send one buttons-up PointerEvent to framebuffer (0,0) before opening Notes or arming input. This unmeasured setup move consumes VMware's dropped-first-move quirk (0017c implementation note at `358d170`, Claude's 2026-10-12 diagnostic); do not await its visible response or retry it. Cap the write at 100 ms within the existing 60-second setup deadline; failure aborts. Then issue the normal positioning move and verify the cursor's intended position before the first setup press. Priming may be dropped or delivered, adds no key/button sample or warmup, and does not change the 200-key quota, latency timing or deadlines. Record it once per fresh boot, never on a same-boot reconnect. QMP and prefix-only Markers scenarios need no priming. Future 0018 baseline setup needs the same unmeasured step, separately from its warmups; its implementation remains deferred.

Click cases allow app lifecycle transitions. Set up one Notes window, arm with one visible key, close it, launch Notes once, then close that window. Each press waits for its expected pixels before the next action. Capture both launch and close presses; only the launch is the host click-response sample. Escape afterwards exits the shell and is itself a final unpaired key. Require two exact `MIRROR_APP_STARTED pid=N kind=0` lines, and for each PID `MIRROR_APP_RECLAIMED pid=N reason=closed status=0 frames_reclaimed=1` followed by `MIRROR_APP_CLOSED pid=N surfaces_reclaimed=1`. Require final `MIRROR_SHELL_CLEANUP_OK apps_reclaimed=1 outcome=Exit(0)`. These are ordered subsequences, not adjacency assertions. Extra launches, faults or alternate cleanup outcomes fail. Existing lifecycle output is permitted and its byte count reported; it is not suppressed or called perf-free timing.

Keys/Exit without burn instead leave their single Notes window open until Escape: one STARTED, then RECLAIMED with `reason=session_ended status=0 frames_reclaimed=1`, CLOSED and successful shell cleanup, with the same exact PID/field rules. With burn, 0019d additionally permits exactly one distinct hidden kind=1 PID and defines its lifecycle subsequence; all other launches remain forbidden. STARTED is never a substitute for rendered-pixel readiness.

Extend `Assert-MirrorPerfMarkers -Items` in `common.ps1` with closed-world INPUT/WINDOW names, full fields/order, bounded counters, scenario-specific origin/lifecycle rules and recomputed accounting. Check the family and teardown order above, including WINDOW before BURN and all retained lines before cleanup/console readiness. Reject missing, repeated or reordered drain suffixes. Repeated INPUT/MEM are bounded sequences, not duplicate singleton markers. Keep 0019a's `Assert-MirrorNoPerf` on every tokenless smoke/capture.

Markers is the explicit prefix-only exception: it never arms input and stops before the setup deadline after its required observations. Its checker allows input still pending, requires no INPUT/WINDOW, and cannot produce an input-performance verdict. This is distinct from a truncated measurement run, which fails.

P9 implementation handoff: update AGENTS.md's capture/When to test sections in the same commit for the added scenarios, 600-second accepted cap, three short cases per profile and targeted Keys/Overlap/Deadline runs. Record default-flavor PerfCapture and the added suite limits below. The host-probe change also documents its separate workspace checks and Phase 1 protocol. Coordinate that hot file with Claude; -PerfCapture and -NoHpet remain 0019a-owned.

3.
