# 0030a: Process and thread table, run queues and wait queues

Status: draft
Depends on: nothing unmerged. The re-plan orders 0019a first in Phase 1 so the phase is measured before and after (roadmap-replan.md, Phase 1), but 0030a builds on main alone.
Ledger: none directly: 0030a is a re-plan NEW spec (roadmap-replan.md, Phase 1 item 2, numbered per RD24). Related: S4 (the policy work stays in 0052), I6 (the capacity this spec starts to lift), G7 (input latency).

## Goal
Processes and threads stop being stack locals of three session loops (`run_pair` kernel/src/userspace.rs:609, `run_desktop` :1178, `run_shell` :1954, cited at HEAD 970e48c) and become entries in kernel-owned global tables, dispatched per thread from one run queue on the boot CPU. A blocked thread waits on a queue attached to the event that completes it, and the event itself wakes it — preempting the running thread when the woken one is eligible — instead of the once-per-loop `wake_threads` poll (:1594). A process runs up to 16 threads. Observable policy is unchanged: 2-tick quanta (:35), the 32-of-100-tick service throttle (:43-44), the 128-tick probe budget (:40), user code on the boot CPU only (`MIRROR_SMP_READY userspace_cpus=1` is unchanged). No syscall is added, removed or renumbered (RS1); the only ABI change is thread-protocol's MAX_THREADS.

## Non-goals
- Userspace on the APs, per-CPU data, per-thread kernel stacks and the per-CPU SYSCALL entry (0051, 0050). The single RSP0 trap stack (stacks.rs:119) and the single ACTIVE-process statics (:56-64), with interrupts-disabled scheduling, stay as they are.
- Priority classes and work-conserving scheduling (0052, S4). The throttle survives here, so its dead time does too: an eligible-again stall of up to 680 ms is unchanged until 0052.
- Kernel heap v2 and frame allocator v2 (Phase 1 items 3-4). The tables are fixed-capacity, allocated once at boot before the heap's growth points close (main.rs:292, :314).
- Spawn, wait, kill, exit status, suspend/resume and the principal field (0030, Phase 3; S6e). Processes are still created only by kernel session seeding; 0030's Phase 3 draft continues this spec's 0030-Dn numbering (split rule 1).
- The vm-protocol limits (0054a) and the 2 MiB image limit (ELF loader v2, Phase 3).

## Decisions
| ID | Decision | Status |
| --- | --- | --- |
| 0030-D1 | A new `kernel/src/sched.rs` owns two fixed-capacity global tables (processes, threads) allocated from the kernel heap once at boot, plus one run queue of ready threads. Threads are scheduled, not processes: dispatch picks the run-queue head and switches address space when its process differs from the current one. The session loops and their process-array cursors (:698, :1258, :2034) and per-process thread cursors (:237-238) are deleted; boot seeds the table per flavor (smoke: init's pair; default: the shell session; agent-demo: open question 1) and one scheduler loop runs until no live process remains. Policy numbers are unchanged: QUANTUM_TICKS=2 (:35), SERVICE_ALLOWANCE/SERVICE_PERIOD 32/100 (:43-44), USER_TICK_BUDGET=128 (:40). Rationale: the smallest step that removes the session-loop structure without changing observable policy. Rejected alternative: keep the three loops and patch each (every later Phase 1 spec would re-patch them). | proposed |
| 0030-D2 | Wait queues replace the `wake_threads` poll (:1594, deleted). Each blocked thread sits on exactly one queue: a per-process futex queue keyed by word address (Waiting, :1730), a per-endpoint IPC queue (Receiving), a per-input-session queue (InputWaiting), the target thread's join queue (Joining), or the global deadline heap (Sleeping, and the deadline of every timed wait). The completing event dequeues and readies the waiter directly: WAKE_U32 (:1767), IPC delivery or close, input arrival, thread exit (the `complete_joins` scan, :1837, becomes a direct wake of the joiner), the timer tick for deadlines, or `invalidate_waits` (:1817) for VM release/PROT_NONE. The Launching/Closing states are completed by ShellRuntime table operations. The Memory state is unchanged: it is a dispatch continuation resumed by `complete_memory`, not a wait queue. Blocked threads still consume zero ticks (the :1619-1623 assertion survives). | proposed |
| 0030-D3 | Wakeup preemption: an event that readies a thread requests a reschedule, honored at the next trap exit (syscall return or IRQ exit, including the deadline's own timer tick). If the woken thread's process is eligible under the throttle, it dispatches immediately; the interrupted thread keeps its remaining quantum, is charged only for ticks used, and rejoins the run-queue head. A woken thread whose process is throttled waits, as today. Rationale: input and IPC latency no longer wait for the waker's quantum or the next poll iteration (G7). Rejected alternative: wake into the run-queue tail (a spinning eligible peer adds up to a quantum of avoidable latency). | proposed |
| 0030-D4 | thread-protocol's MAX_THREADS rises from 4 to 16 per process (crates/thread-protocol/src/lib.rs:23); WAKE_U32's count bound follows it (lib.rs:41-43). The per-process fixed array (:236) becomes a bounded TID list in the process entry; the global tables hold 64 processes and 256 threads. Table-full returns EAGAIN, as slot-full does today (:1887-1891). TIDs stay monotonic u64, so a reused slot never satisfies a stale ID; join keeps its stale-TID rejection (readme.md:203). Rationale for fixed capacity: heap v2 and 0054a, which could grow or charge the tables, land after this spec in Phase 1. Rejected alternatives: .bss statics (they inflate every kernel image by the table size) and heap growth at runtime (the heap cannot grow after boot today). | proposed |
| 0030-D5 | A finished process stays in the table as a zombie holding its Outcome until reaped. The smoke harness validates zombies (`validate_process`, :2212) and then reaps them; the frame-baseline assertion (snapshotted at :624, checked at :774-779) moves to "the table is empty". In the default flavor the desktop's finish still ends the session and the kernel idles. Reaping a process destroys its address space and returns its frames exactly as today. | proposed |
| 0030-D6 | Every wait queue wakes FIFO; the per-process `next_waiter` round-robin (:251, :1785) is deleted. Cancellation results are unchanged: timeout completes with ETIMEDOUT, invalidation with EFAULT, IPC close as today, each with zero ticks charged. Rationale: FIFO wake order is predictable and testable from userspace. Rejected alternative: keep round-robin from a cursor (its order depends on history nothing can observe). | proposed |

## Interfaces
- `kernel/src/sched.rs` (new): the tables, run queue, deadline heap and wait queues; `resume`/`suspend`/`timer_tick` (userspace.rs:887, :3489, :3441) become its operations on the active thread. The ACTIVE statics and the IF=0, BSP-only discipline are unchanged.
- `kernel/src/userspace.rs`: `Process` loses `threads` (:236), `current_thread`/`next_thread` (:237-238) and `next_waiter` (:251), and keeps its address space, VM ledger, handles, policy and counters; `Thread` gains its table links. `ShellRuntime::launch`/`reclaim`/`close` (:1417, :1488, :1539) insert and reap table entries; syscall arms and their error codes are unchanged.
- `kernel/src/main.rs`: `run_init` (:370), `run_desktop` (:399) and `run_shell` (:409) are replaced by table seeding per flavor plus one `sched::run`.
- `crates/thread-protocol/src/lib.rs`: MAX_THREADS = 16; its host tests follow the constant.
- `userspace/init/src/threads.rs` and `sync.rs`: the capacity checks (:455, :466) expect 16 slots and EAGAIN at the 17th; new checks below. The probe bound (main.rs:1107-1109) is unchanged: every new check joins the existing per-probe battery (RS1: new test code extends init's battery).
- Scripts: `run.ps1` and `capture.ps1` marker lists add `MIRROR_SCHED_READY` and, in smoke boots, `MIRROR_PREEMPT_OK`. No scenario, `-Fault` or test.ps1 case changes.
- Markers: `MIRROR_SCHED_READY processes=64 threads=256 max_threads=16` prints once per boot in every flavor (content-free). `MIRROR_PREEMPT_OK wake_lateness=<n> ipc_lateness=<n>` prints in boot-smoke after test 4. `MIRROR_SCHEDULER_OK` and `MIRROR_USER_THREADS_OK` keep their meanings.
- readme.md lines 7, 203 and 213: "four thread slots" becomes sixteen threads in a global table; the scheduler-marker description is unchanged. AGENTS.md changes only under open question 1 (P9).

## Acceptance tests
1. The existing battery passes with unchanged semantics: threads, sync, TLS, FPU and paging checks, probes 7 and 18-20 with the same outcomes, `MIRROR_USER_THREADS_OK`, `MIRROR_SCHEDULER_OK` and exact frame restoration. `validate_process` keeps every assertion, now reading outcomes from zombies.
2. Capacity: one process runs 16 threads, each parked on its own futex word; the 17th create returns EAGAIN; WAKE_U32 with count 16 is accepted and count 17 EINVAL. threads.rs:455/:466 are updated to the new bound.
3. Wait queues: 8 threads wait on one word; one WAKE_U32 (count 16) wakes all 8 in FIFO order; a blocked thread's charged ticks do not move; a 5-tick timeout completes ETIMEDOUT; release and PROT_NONE still cancel with EFAULT (sync.rs's invalidation checks unchanged).
4. Wakeup preemption (new checks in the existing battery): with an eligible spinning peer thread, a sleeping thread's deadline is met by the deadline tick's own trap exit, and the spinner resumes with its remaining quantum; a receiver blocked on RECV_WAIT is dispatched at its sender's trap exit. Both latencies are measured in ticks and summarised in `MIRROR_PREEMPT_OK wake_lateness=<n> ipc_lateness=<n>`; the script requires each to be at most 1 (an IRQ delayed across a tick boundary by a critical section).
5. Table bounds: a boot-smoke kernel self-test (the `stacks::self_test` pattern, 0016a item 5) fills the process table to 64 and the thread table to 256, expects EAGAIN, destroys every entry and checks the boot frame baseline is restored exactly.
6. Zombie/reap: the fault scenarios leave their Outcome in a zombie until validation; after reap and session drain, `frames.stats().allocated_frames` equals the boot baseline (today's :624/:774-779 pattern at table-empty).
7. Before merge (P8): the full `scripts/test.ps1` in debug and release; `test.ps1 -AgentDemo` as well unless open question 1 retires the flavor. The new markers join the run.ps1/capture.ps1 lists in the same commit (closed-world rule).
