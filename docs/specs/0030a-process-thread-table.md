# 0030a: Process and thread table, run queues and wait queues

Status: draft (revised after claude's review of 3dd1d42)
Depends on: 0019a (Phase 1 item 1; RD8 and 0019a's decisions are confirmed first — its perf hooks sit in the session loops this spec deletes, see Interfaces). The code change builds on main alone.
Ledger: S6 as amended 2026-10-11 (Phase 1 adds no syscall and changes only the thread-protocol and vm-protocol limits), decisions.md Phases row 1 (process and thread table), S7/S7a/S7b (marker gating). Related: S4 (the policy work stays in 0052), G7 (input latency).

Line references are at HEAD 970e48c. Dependent specs cite this spec's decisions as 0030-Dn (split rule 1; 0030's Phase 3 draft continues the numbering).

## Goal
Processes and threads stop being stack locals of three session loops (`run_pair` kernel/src/userspace.rs:609, `run_desktop` :1178, `run_shell` :1954) and become entries in kernel-owned global tables, dispatched per thread from one run queue on the boot CPU. A blocked thread waits on a queue attached to the event that completes it, and the event marks it ready — with a reschedule at the next trap exit — instead of the once-per-loop `wake_threads` poll (:1594). A process runs up to 16 threads. The policy numbers are unchanged: 2-tick quanta (:35), the 32-of-100-tick service throttle (:43-44), the 128-tick probe budget (:40), user code on the boot CPU only (`MIRROR_SMP_READY userspace_cpus=1` is unchanged). Dispatch and wake order do change (D1, D3, D6). No syscall is added, removed or renumbered (S6, amended); the only ABI changes are thread-protocol's MAX_THREADS and vm-protocol's MAX_REGIONS (0030-D4).

## Non-goals
- Userspace on the APs, per-CPU data, per-thread kernel stacks and the per-CPU SYSCALL entry (0051, 0050). The single RSP0 trap stack (stacks.rs:119) and the single ACTIVE-process statics (:56-64), with interrupts-disabled scheduling, stay as they are.
- Priority classes and work-conserving scheduling (0052, S4). The throttle survives here, so its dead time does too: an eligible-again stall of up to 680 ms is unchanged until 0052.
- Kernel heap v2 and frame allocator v2 (Phase 1 items 3-4). The tables are fixed-capacity .bss statics, so they need neither.
- Spawn, wait, kill and exit status (0030, Phase 3), suspend/resume (S6e) and the principal field (RD2, proposed, due before Phase 1). Processes are created only by kernel session seeding and the shell's launch call (:1417, :2046-2052). 0030's Phase 3 draft continues this spec's 0030-Dn numbering (split rule 1).
- The vm-protocol capacity limits RESERVED_LIMIT/COMMITTED_LIMIT (0054a); MAX_REGIONS rises here (0030-D4). The 2 MiB image limit stays for the ELF loader v2 (Phase 3).

## Decisions
| ID | Decision | Status |
| --- | --- | --- |
| 0030-D1 | A new `kernel/src/sched.rs` owns two fixed-capacity global tables (processes, threads) as .bss statics, plus one run queue of ready threads. Threads are scheduled, not processes: dispatch picks the first run-queue thread whose process is eligible under the throttle (a bounded scan of at most 256 entries; `policy.eligible` stays the gate, as at :1283 and :1583-1589, so the "throttled service resumed" assertion at :207 can never trip), and the kernel idles in HLT when none is eligible, as today (:723, :1304, :2107). The session loops and their process-array cursors (:698, :1258, :2034) and per-process thread cursors (:237-238) are deleted. Sessions stay sequential: `sched::run(session)` is called once per session with its context (the session's `Ipc` plus, for the desktop sessions, the surface, input and windows sessions and the ShellRuntime), and returns with that session's processes drained and reaped. A boot's order is main.rs's own: boot-smoke runs the init pair and the relaunch pair, then report_entry_ac, the after_userspace rendezvous and the heap growth (main.rs:378-388), then every kernel — smoke, trace and default alike — runs the shell session, or the desktop+agent session when the agent-demo feature is on (S7a; agent-demo is a feature, not a flavor). The kernel root is restored on every return to the scheduler, as today (:943-944); "switch address space" refers only to which user root is loaded at dispatch, and the copy_to/from_user and vm.rs:244/:280 contracts are unchanged. Rationale: the smallest step that removes the session-loop structure without changing the policy numbers. Rejected alternatives: keep the three loops and patch each (every later Phase 1 spec would re-patch them); heap-allocated tables (a permanent heap allocation breaks `capacity_self_test`'s used==0 invariant, heap.rs:587-672 — .bss is NOBITS, so it grows no image and touches no heap). | proposed |
| 0030-D2 | Wait queues replace the `wake_threads` poll (:1594, deleted). Each blocked thread sits on exactly one event queue — a per-process futex queue keyed by word address (Waiting, :1730), a per-endpoint IPC queue (Receiving), a per-input-session queue (InputWaiting), or the target thread's join queue (Joining) — plus the global deadline heap when its wait has a timeout (Sleeping always; PendingReceive/PendingInput always carry one, :153/:160; PendingWait optionally, :164-167). Whichever completes first removes it from both. The completing event only marks the waiter and requests a reschedule: IRQ handlers and syscalls never dequeue, copy or reap in place. The dequeue, user copy, state change, joiner wake and reap run in the scheduler, which processes the queues and the deadline heap after every `resume_user` return (:936-944), after every idle HLT wakeup, and whenever the tick preempts — the thread being exited is reaped only after its context is saved and its pointer released (:909-916, :1834-1836), and the receiver's copy still runs against the receiver's own table entry (:2976-3018), with no IPC delivery inside a sender's syscall. Handlers reach the tables through a published pointer of the ACTIVE kind (:56-64); the scheduler touches queues only while no user thread runs, and the published entry is never the one being resumed. The precedence rules are unchanged: for IPC and input waits, readiness or closure beats a timeout expiring in the same check; for address waits, an elapsed deadline beats an explicit wake and is not counted (readme.md:516, :554; wake_word :1798-1803). Process finish and zombie handling unlink every thread of the process from every queue and the run queue, so a stale link can never wake a reused slot (threads.rs PARK, :333-343). Blocked threads still consume zero ticks, asserted in the common completion helper (the :1716-1721 pattern, moved out of the deleted :1619-1623). | proposed |
| 0030-D3 | Wakeup preemption: a completion pass that readies threads appends them to the run queue in wake order and honors the pending reschedule at the next trap exit (syscall return or IRQ exit, including the deadline's own tick): the first eligible woken thread dispatches, and the interrupted thread keeps its remaining quantum, is charged only for ticks used, and rejoins the run queue behind the just-woken set. A woken thread whose process is throttled waits, as today. Rationale: input and IPC latency no longer wait for the waker's quantum or the next poll iteration (G7). Rejected alternative: wake into the run-queue tail behind the interrupted thread (a spinning eligible peer adds up to a quantum of avoidable latency). | proposed |
| 0030-D4 | thread-protocol's MAX_THREADS rises from 4 to 16 per process (crates/thread-protocol/src/lib.rs:23); WAKE_U32's count bound follows it (lib.rs:41-43). vm-protocol's MAX_REGIONS rises from 32 to 64 (crates/vm-protocol/src/lib.rs:16), so a process can hold 16 guarded stacks alongside its working set even where guard regions do not merge. The existing init battery is decoupled from the ABI constants: its TASKS arrays are sized by a local 3 (threads.rs:79, sync.rs:49) so its semantics, indexing (threads.rs:80, :160-161) and stage checks are unchanged. The 16-thread capacity check is new and separate: its 15 stacks live in one RW reservation (one region, no guards), released before sync.rs runs, so the check fits the region limit with the battery's own 31+2 regions (adjacent PROT_NONE guards merge, vm.rs:67-77) and never touches the 33-region path (sync.rs:226). The global tables hold 64 processes and 256 threads as .bss statics — Thread is about 768 bytes (208-byte TrapFrame, interrupts.rs:161, plus the 512-byte FXSAVE image, fpu.rs:38-40) and Process about 2.5 KiB with its 64-entry region ledger (vm.rs:51), roughly 350 KiB of NOBITS in all: no image bytes, no heap, and `capacity_self_test`'s used==0 invariant and the after_userspace growth test's contiguous-free precondition (heap.rs:510-516) are untouched. Creating a process reserves its process slot and main-thread slot together before `create_process` (:468-606); on failure the partially created address space and application resources are destroyed (the :1466-1474 rollback pattern). Table-full returns EAGAIN, as slot-full does today (:1887-1891). TIDs stay monotonic u64, so a reused slot never satisfies a stale ID; join keeps its stale-TID rejection (readme.md:203). Rejected alternative: heap allocation at runtime (the heap cannot grow after boot today, and permanent heap use breaks `capacity_self_test`). | proposed |
| 0030-D5 | A finished process stays in the table as a zombie holding its Outcome until reaped. At each session's drain the smoke harness validates zombies (`validate_process`, :2212) and then reaps them, and the frame-baseline assertion (snapshotted at :624, checked at :774-779) applies per session: before the next session seeds, that session's entries are reaped and its frames restored. When the shell session ends, the default kernel starts its diagnostic console when a keyboard or mouse is ready (main.rs:511-520), and idles only when no input device is ready. Reaping a process destroys its address space and returns its frames exactly as today. | proposed |
| 0030-D6 | Wait queues wake FIFO. This is kernel behavior checked only by the smoke battery: the ABI text keeps "no FIFO promise" (readme.md:516 is not reworded), and S6's limits-only scope is kept. Cancellation results are unchanged: timeout completes with ETIMEDOUT, invalidation with EFAULT, IPC close as today, each with zero ticks charged. Rationale: a deterministic order makes the battery checkable without promising userspace anything. Rejected alternative: keep the `next_waiter` cursor round-robin (:251, :1785), whose order depends on history nothing can observe. | proposed |

## Interfaces
- `kernel/src/sched.rs` (new): the tables, run queue, deadline heap and wait queues; `resume`/`suspend`/`timer_tick` (userspace.rs:887, :3489, :3441) become its operations on the active thread. The ACTIVE statics and the IF=0, BSP-only discipline are unchanged.
- `kernel/src/userspace.rs`: `Process` loses `threads` (:236), `current_thread`/`next_thread` (:237-238) and `next_waiter` (:251), and keeps its address space, VM ledger, handles, policy and counters; `Thread` gains its table links. `ShellRuntime::launch`/`reclaim`/`close` (:1417, :1488, :1539) insert and reap table entries; syscall arms and their error codes are unchanged.
- `kernel/src/main.rs`: `run_init` (:370), `run_desktop` (:399) and `run_shell` (:409) become per-session seeding plus `sched::run(session)`, keeping main.rs's current order (0030-D1).
- 0019a's hooks move with the loops they live in (0019-perf-instrumentation-and-telemetry.md:80, :106, :86): the memory sampler, the idle-point flush of the D7 input ring and the D6 frame/shell_ready hooks move from run_shell/run_desktop into `sched::run`'s idle and dispatch paths, with unchanged output and passing perf-family checks.
- `crates/thread-protocol/src/lib.rs`: MAX_THREADS = 16; its host tests follow the constant.
- `crates/vm-protocol/src/lib.rs`: MAX_REGIONS = 64; its host tests follow the constant. The kernel's `Vm` grows its inline region ledger accordingly (vm.rs:51).
- `userspace/init/src/threads.rs` and `sync.rs`: TASKS sized by a local 3 (threads.rs:79, sync.rs:49); the capacity checks at threads.rs:455/:466 move into the new 16-thread check. The probe bound (main.rs:1107-1109) is unchanged: every new check joins the existing per-probe battery (S6: new test code extends init's battery).
- Scripts and scans: `MIRROR_SCHED_READY processes=64 threads=256 max_threads=16 regions=64` prints once per boot in every flavor and joins test.ps1's Default and Trace `$required` lists (test.ps1:22-55); run.ps1 and capture.ps1 each check it exactly once with its full field list, the MIRROR_SMP_READY pattern (run.ps1:78-80). `MIRROR_PREEMPT_OK wake_lateness=<n> ipc_lateness=<n>` is boot-smoke only: it joins test.ps1's `$forbidden` lists for trace and default kernels and capture.ps1:696's absence list, prints exactly twice per smoke boot (once per pair session's role-0 process, test 4), and is not required in `$fatalKernelFault` cases (run.ps1:646-651). No new test.ps1 cases; its kernel-image string lists change. The hygiene probe requires exactly one `MIRROR_SCHED_READY`.
- readme.md: the status paragraph (:7, "four thread slots" becomes sixteen threads in a global table), the ABI lines :497 and :514 (slot counts), :516 (wake-count bound only; the no-FIFO contract stays) and :554 (scheduling description), and :213's required-marker list. AGENTS.md changes only under open question 1 (P9).

Work order (one commit per step, each running its targeted cases, P8; the rewrite takes small steps under the full suite, roadmap-replan.md:398):
1. MAX_THREADS=16 and MAX_REGIONS=64, thread-protocol and vm-protocol host tests, and the init battery decoupling — on today's arrays.
2. sched.rs tables and one run queue; session loops deleted; policy numbers unchanged.
3. Wait queues replace wake_threads.
4. Wakeup preemption and MIRROR_PREEMPT_OK.
5. Zombie/reap and the table-bounds self-test.
Then the full suite.

## Acceptance tests
1. The existing battery passes with unchanged semantics: threads, sync, TLS, FPU and paging checks, probes 7 and 18-20 with the same outcomes, `MIRROR_USER_THREADS_OK`, `MIRROR_SCHEDULER_OK` and exact frame restoration, and both wake-precedence rules of readme.md:516/:554. `validate_process` keeps every assertion, now reading outcomes from zombies.
2. Capacity (the new separate check): one process runs 16 threads, the 17th create returns EAGAIN, WAKE_U32 with count 16 is accepted and count 17 EINVAL, and the check's single stack reservation is released before sync.rs runs. The pre-existing battery is unchanged (TASKS stays 3).
3. Wait queues: 8 threads wait on one word, launched one at a time with `settle()` (sync.rs:74-80) between them; one WAKE_U32 (count 16) wakes all 8 in FIFO order, proven by a shared sequence counter; a blocked thread's charged ticks do not move; a 5-tick timeout completes ETIMEDOUT; release and PROT_NONE still cancel with EFAULT (sync.rs's invalidation checks unchanged).
4. Wakeup preemption, in role 0 only with role 1 blocked: with an eligible spinning peer thread, a sleeping thread's deadline is met by the deadline tick's own trap exit, and the spinner (bounded, well inside the shared 128-tick budget) resumes with its remaining quantum; a receiver blocked on RECV_WAIT is dispatched at its sender's trap exit, measured on one of the IPC battery's existing three messages so the message counts (:834-847) are unchanged. Both latencies are measured kernel-side (dispatch tick minus deadline; receiver dispatch tick minus the sender's trap-exit tick), recorded only for battery-flagged threads (the fpu_preemption_start pattern, :273-275), and printed as `MIRROR_PREEMPT_OK` — exactly two lines per smoke boot, each value at most 1 tick (an IRQ delayed across a tick boundary by a critical section).
5. Table bounds: a boot-smoke kernel self-test (the `stacks::self_test` pattern, 0016a item 5) fills the process table to 64 and the thread table to 256, expects EAGAIN, destroys every entry and checks the boot frame baseline is restored exactly; a second case creates a process while the thread table is full and checks the same exact restoration. `heap::capacity_self_test` (heap.rs:587-672) is unaffected: the tables are .bss.
6. Zombie/reap: the fault scenarios leave their Outcome in a zombie until validation; each session drains with its frames restored to its baseline (today's :624/:774-779 pattern, per session).
7. 0019a continuity: with a `mirror.perf=` token, the input-to-present trace (with `burn`) is recorded in QEMU before and after this spec and reported, not gated — the reason the phase measures 0019a first.
8. Before merge (P8): the full `scripts/test.ps1` in debug and release; `test.ps1 -AgentDemo` as well unless open question 1 retires the feature — in the RS6-yes branch, the last `-AgentDemo` run is on the commit before the deletion. The marker and scan-list changes land in the same commit (closed-world rule).
