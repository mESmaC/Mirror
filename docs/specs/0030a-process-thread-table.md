# 0030a: Process and thread table, run queues and wait queues

Status: confirmed (2026-10-12); implemented, on `main` @34f7de0 (2026-10-12, claude). 0050 amended D3 in 61ddc76 (D3's row says how).
Depends on: 0019a (Phase 1 item 1; RD8 and 0019a's decisions are confirmed first — its perf hooks sit in the session loops this spec deletes, see Interfaces). The code change builds on main after 0019a merges.
Ledger: S6 as amended 2026-10-11 (Phase 1 adds no syscall and changes only the thread-protocol and vm-protocol limits), decisions.md Phases row 1 (process and thread table), S7/S7a/S7b (marker gating). Related: S4 (the policy work stays in 0052), G7 (input latency).

Line references are at HEAD 970e48c. Dependent specs cite this spec's decisions as 0030-Dn (split rule 1; 0030's Phase 3 draft continues the numbering).

## Goal
Processes and threads stop being stack locals of three session loops (`run_pair` kernel/src/userspace.rs:609, `run_desktop` :1178, `run_shell` :1954) and become entries in kernel-owned global tables, dispatched per thread from one run queue on the boot CPU. A blocked thread waits on a queue attached to the event that completes it, and the event marks it ready — with a reschedule at the next trap exit — instead of the once-per-loop `wake_threads` poll (:1594). A process runs up to 16 threads. The policy numbers are unchanged: 2-tick quanta (:35), the 32-of-100-tick service throttle (:43-44), the 128-tick probe budget (:40), user code on the boot CPU only (`MIRROR_SMP_READY userspace_cpus=1` is unchanged). Dispatch and wake order do change (D1, D3, D6). No syscall is added, removed or renumbered (S6, amended); the only ABI changes are thread-protocol's MAX_THREADS and vm-protocol's MAX_REGIONS (0030-D4).

## Non-goals
- Userspace on the APs, per-CPU data, per-thread kernel stacks and the per-CPU SYSCALL entry (0051, 0050). The single RSP0 trap stack (stacks.rs:119) and the single ACTIVE-process statics (:56-64), with interrupts-disabled scheduling, stay as they are.
- Priority classes and work-conserving scheduling (0052, S4). The throttle survives here, so its dead time does too: an eligible-again stall of up to 680 ms is unchanged until 0052.
- Kernel heap v2 and frame allocator v2 (Phase 1 items 4-5). The tables are fixed-capacity .bss statics, so they need neither.
- Spawn, wait, kill and exit status (0030, Phase 3), suspend/resume (S6e) and the principal field (RD2, confirmed 2026-10-12). Processes are created only by kernel session seeding and the shell's launch call (:1417, :2046-2052). 0030's Phase 3 draft continues this spec's 0030-Dn numbering (split rule 1).
- The vm-protocol capacity limits RESERVED_LIMIT/COMMITTED_LIMIT (0054a); MAX_REGIONS rises here (0030-D4). The 2 MiB image limit stays for the ELF loader v2 (Phase 3).

| 0030-D1 | A new `kernel/src/sched.rs` owns two fixed-capacity global tables (processes, threads) as .bss statics, plus one run queue of ready threads. Threads are scheduled, not processes: dispatch picks the first run-queue thread whose process is eligible under the throttle (a bounded scan of at most 256 entries; `policy.eligible` stays the gate, as at :1283 and :1583-1589, so the "throttled service resumed" assertion at :207 can never trip), and the kernel idles in HLT when none is eligible, as today (:723, :1304, :2107). The session loops and their process-array cursors (:698, :1258, :2034) and per-process thread cursors (:237-238) are deleted. Sessions stay sequential: `sched::run(session) -> stats` is called once per session with its context — the session's `Ipc`, the optional surface session (both desktop sessions; and the init pair's, published for both processes with use gated by the surface handle, :657-667, :740-748), the input and windows sessions and the ShellRuntime (the shell session only: the agent-demo session has neither — its desktop gets surface and input, its agent neither, :1290-1298) — with the per-process access mapping (the shell holds surface, input and windows; its apps hold only windows, :2084-2102) so dispatch publishes ACTIVE_SURFACE/INPUT/WINDOWS correctly per process — and returns stats { `switches` (process changes, counted as at :736-739) and `idle_ticks` } for `MIRROR_SCHEDULER_OK` (:872-881). The end rule is per session: a pair ends when both its processes finish (:702); the shell session ends when the shell finishes (`while !desktop.finished()`, :2035), then closes its live children with `Outcome::SessionEnded` (:2110-2120, readme.md:554) and drains; the desktop session ends when the desktop finishes (:1259), then ends the agent with SessionEnded (:1312-1315). These match the capture paths, which end sessions with apps open (capture-shell.ps1:261-265; capture.ps1:442-451, :677-679). A boot's order is main.rs's own: boot-smoke runs the init pair and the relaunch pair, then report_entry_ac, the after_userspace rendezvous and the heap growth (main.rs:378-388), then every kernel — smoke, trace and default alike — runs the shell session, or the desktop+agent session when the agent-demo feature is on (S7a; agent-demo is a feature, not a flavor); on the missing-display-or-input path no session is seeded (MIRROR_DESKTOP_SKIPPED, main.rs:397, :419-421). `MIRROR_SCHED_READY` prints once when the tables are set up, before the first session, so it prints on that path too. The kernel root is restored on every return to the scheduler, as today (:943-944); "switch address space" refers only to which user root is loaded at dispatch, and the copy_to/from_user and vm.rs:244/:280 contracts are unchanged. Rationale: the smallest step that removes the session-loop structure without changing the policy numbers. Rejected alternatives: keep the three loops and patch each (every later Phase 1 spec would re-patch them); heap-allocated tables (a permanent heap allocation breaks `capacity_self_test`'s used==0 invariant, heap.rs:587-672 — .bss is NOBITS, so it grows no image and touches no heap). | confirmed (2026-10-12) |
| 0030-D2 | Wait queues replace the `wake_threads` poll (:1594, deleted). Each blocked thread sits on exactly one event queue — a per-process futex queue keyed by word address (Waiting, :1730), a per-endpoint IPC queue (Receiving), a per-input-session queue for device input and a per-app event queue woken by `application_event` (:2847-2867), both under InputWaiting (:3247-3262, :1674-1680), or the target thread's join queue (Joining) — plus the global deadline heap when its wait has a timeout (Sleeping always; PendingReceive/PendingInput always carry one, :153/:160; PendingWait optionally, :164-167). Whichever completes first removes it from both. The completing event only marks the waiter and requests a reschedule: a handler never completes *another* thread's wait in place — the dequeue, user copy, state change and joiner wake for a *woken* thread run in the scheduler, which processes the queues and the deadline heap after every `resume_user` return (:936-944), after every idle HLT wakeup, and whenever the tick preempts — the thread being exited is reaped only after its context is saved and its pointer released (:909-916, :1834-1836), and the receiver's copy still runs against the receiver's own table entry (:2976-3018), with no IPC delivery inside a sender's syscall. Today's same-thread in-place completions are unchanged: SEND copies the sender's bytes in its own syscall (:2958-2967), RECV/RECV_WAIT with a queued message completes in the caller's (:2996-3015), and JOIN of an already-exited thread still reaps it in the joiner's syscall (:1921-1928), safe because the exited thread's context was saved at its exit. The Launching, Closing and Memory states stay deferred completions: the session's ShellRuntime operations complete Launching and Closing (as at :2045-2061) and `complete_memory` completes Memory (:950-952), now both called from `sched::run`. Input arrival joins the wake paths: the PS/2 IRQ drains bytes as today (interrupts.rs:1071-1077) and sets a static atomic input-pending flag (no session pointer — the input::Session's pointer is published only while the shell (agent-demo: the desktop) runs, :921-927, :1296, :2084-2092, and the IRQ must work during an app's slice and between sessions); the scheduler clears the flag with IF=0 before it checks the input queue, and `application_event` (:2847-2867) is the waker for app input. When the IRQ interrupted CPL3, it requests a reschedule after `timer::handle_irq`'s EOI (interrupts.rs:1077) — never inside it (timer.rs:284-285) — by suspending the interrupted thread with `State::Ready`, charging no tick, changing no quantum and counting no preemption or throttle (unlike `timer_tick`, :3445-3462); a PS/2 IRQ fires per byte, not per tick, so charging would spend the shell's 32-tick allowance on input bytes. When nothing woke, the interrupted thread is dispatched first (D3's "behind the just-woken set" with an empty set). The reschedule is skipped when no thread waits on device input, read from a static atomic count of device-input waiters kept beside the flag (the IRQ reads only that; app-input waits do not count). Handlers reach the tables through a new published static beside ACTIVE (:56-64), set only across `resume_user` (as ACTIVE is, :897, :929, :942) and cleared right after, so a CPL0 IRQ handler — during the scheduler's idle HLT or a heap-growth shootdown wait — never aliases the scheduler's borrow: a CPL0 IRQ handler touches no scheduler state except atomics (TICKS, the input flag, the waiter count), and syscall and CPL3 IRQ paths (sched.rs's trap-time operations) reach single entries through raw slot pointers (thread links, wait-queue heads, the reschedule flag), never a whole-table `&mut` and never the active entry while a `with_active` borrow is live (:2494-2507, :3057-3059). The scheduler never touches the tables while a user thread runs, and keeps the FPU image it hands to `resume_user` outside the tables (:913-916) — the ACTIVE statics' own discipline is unchanged. The precedence rules are unchanged: for IPC and input waits, readiness or closure beats a timeout expiring in the same check; for address waits, an elapsed deadline beats an explicit wake and is not counted (readme.md:516, :554; wake_word :1798-1803). Process finish and zombie handling unlink every thread of the process from every queue and the run queue, so a stale link can never wake a reused slot (threads.rs PARK, :333-343). Blocked threads still consume zero ticks, asserted in the common completion helper (the :1716-1721 pattern, moved out of the deleted :1619-1623). | confirmed (2026-10-12) |
| 0030-D3 | Wakeup preemption: a completion pass that readies threads appends them to the run queue in wake order and honors the pending reschedule at the next trap exit (syscall return or IRQ exit, including the deadline's own tick and the input IRQ's flag, 0030-D2): the first eligible woken thread dispatches, and the interrupted thread keeps its remaining quantum, is charged only for ticks used, and rejoins the run queue behind the just-woken set. A woken thread whose process is throttled waits, as today. Rationale: input and IPC latency no longer wait for the waker's quantum or the next poll iteration (G7). Rejected alternative: wake into the run-queue tail behind the interrupted thread (a spinning eligible peer adds up to a quantum of avoidable latency). (Amended 2026-10-12 by claude during 0050: the interrupted thread rejoins at the head of the run queue, so it resumes right after the first eligible woken thread, ahead of every entry queued before it ran, as D2 reads this rule when nothing woke. Queued at the tail, it lost that place once the next completion pass began, and a deadline that displaced a just-woken waiter before its first instruction reordered acceptance 3's FIFO check.) | confirmed (2026-10-12) |
| 0030-D4 | thread-protocol's MAX_THREADS rises from 4 to 16 per process (crates/thread-protocol/src/lib.rs:23); WAKE_U32's count bound follows it (lib.rs:41-43). vm-protocol's MAX_REGIONS rises from 32 to 64 (crates/vm-protocol/src/lib.rs:16): a 16-thread process needs 15 guarded worker stacks (the main thread runs on the fixed ELF stack, userspace.rs:22-23, :496), at 31 regions when packed the way init packs them (threads.rs:196-201; adjacent PROT_NONE guards merge, vm.rs:67-77) and 45 when they do not merge, so 64 leaves headroom. (The battery itself, with its TASKS sized by a local 3, peaks at 9 regions: sync.rs packs 3 guarded stacks into 7 (:381-385) and the MEMORY split adds 2 (:217-226); threads.rs peaks at 8 (:196-201, :477).) The existing init battery is decoupled from the ABI constants: its TASKS arrays are sized by a local 3 (threads.rs:79, sync.rs:49) so its semantics, indexing (threads.rs:80, :160-161) and stage checks are unchanged. The 16-thread capacity check is new and separate: its 15 stacks live in one RW reservation (one region, no guards), released before sync.rs runs, and acceptance 3's 8 waiters use another, so the checks add two transient regions, each released in turn, to a battery that peaks at 9. The global tables hold 64 processes and 256 threads. Their storage form: a `static` table of `MaybeUninit` slots plus an all-zero occupancy bitmap, zero-initialized so it lands in .bss (NOBITS, no file bytes — `Option<Thread>::None` is not all-zero, since the `joiner` niche stores 2, so a `[None; 256]` table would land in .data), inside a wrapper whose Sync contract matches ACTIVE's: scheduler-only, BSP, IF=0. A process entry holds the kernel `PageTables` by raw pointer with the SAFETY argument that the kernel tables outlive every session (main.rs:155-174) and that only the scheduler, on the BSP with IF=0, ever dereferences it; `Process<'kernel>`'s borrow (paging.rs:817-818) cannot itself live in a `'static` slot. Size: 256 threads x 816 B plus 64 processes x about 2.4 KiB (the 64-entry region ledger, vm.rs:51, plus handles and counters) is about 0.36 MiB, and `capacity_self_test`'s used==0 invariant (heap.rs:587-672) and the after_userspace growth test's contiguous-free precondition (heap.rs:510-516) are untouched. Creating a process reserves its process slot and main-thread slot together before `create_process` (:468-606); on failure the partially created address space and application resources are destroyed (the :1466-1474 rollback pattern). Table-full returns EAGAIN, as slot-full does today (:1887-1891). TIDs stay monotonic u64, so a reused slot never satisfies a stale ID; join keeps its stale-TID rejection (readme.md:203). Rejected alternative: heap allocation (the heap grows only at explicit boot points today, and permanent heap use breaks `capacity_self_test`). | confirmed (2026-10-12) |
| 0030-D5 | A finished process stays in the table as a zombie holding its Outcome until reaped. At each session's drain the smoke harness validates zombies (`validate_process`, :2212) and then reaps them, keeping today's closing checks: the session's `Ipc` is drained, every handle table is empty and the ACTIVE_* pointers are null before teardown (:763-775, :2121-2125), and the frame-baseline assertion (snapshotted at :624, checked at :774-779) applies per session: before the next session seeds, that session's entries are reaped and its frames restored. When the shell session ends, default and trace kernels start the diagnostic console when a keyboard or mouse is ready (main.rs:511-520; smoke kernels go on to the capacity self-test, main.rs:424-428), and the kernel idles only when no input device is ready. Reaping a process destroys its address space and returns its frames exactly as today. | confirmed (2026-10-12) |
| 0030-D6 | Wait queues wake FIFO. This is kernel behavior checked only by the smoke battery: readme.md:516 makes no ordering promise (its "round-robin slot order" becomes "an unspecified order", keeping "no FIFO promise"), and S6's limits-only scope is kept. Cancellation results are unchanged: timeout completes with ETIMEDOUT, invalidation with EFAULT, IPC close as today, each with zero ticks charged. Rationale: a deterministic order makes the battery checkable without promising userspace anything. Rejected alternative: keep the `next_waiter` cursor round-robin (:251, :1785), whose order depends on history nothing can observe. | confirmed (2026-10-12) |

## Interfaces
- `kernel/src/sched.rs` (new): the tables, run queue, deadline heap and wait queues; `resume`/`suspend`/`timer_tick` (userspace.rs:887, :3489, :3441) become its operations on the active thread. The ACTIVE statics and the IF=0, BSP-only discipline are unchanged.
- `kernel/src/userspace.rs`: `Process` loses `threads` (:236), `current_thread`/`next_thread` (:237-238) and `next_waiter` (:251), and keeps its address space, VM ledger, handles, policy and counters; `Thread` gains its table links. `ShellRuntime::launch`/`reclaim`/`close` (:1417, :1488, :1539) insert and reap table entries; syscall arms and their error codes are unchanged.
- `kernel/src/main.rs`: `run_init` (:370), `run_desktop` (:399) and `run_shell` (:409) become per-session seeding plus `sched::run(session)`, keeping main.rs's current order (0030-D1). `sched::run` takes the kernel `&PageTables`, `&mut FrameAllocator` and the HHDM offset the loops hold today (:609-617), so heap v2's safe points meet `grow`'s contract (0059-D1).
- `kernel/src/paging.rs`: `UserAddressSpace<'kernel>` drops its lifetime (paging.rs:817-818): the entry holds the kernel `PageTables` by raw pointer, with the SAFETY argument of 0030-D4.
- 0019a's hooks move with the loops they live in (0019-perf-instrumentation-and-telemetry.md:80, :106, :86): the memory sampler, the idle-point flush of the D7 input ring and the D6 frame/shell_ready hooks move from run_shell/run_desktop into `sched::run`'s idle and dispatch paths, with unchanged output and passing perf-family checks.

- `crates/vm-protocol/src/lib.rs`: MAX_REGIONS = 64. ## Acceptance tests
1. The existing battery passes with unchanged semantics: threads, sync, TLS, FPU and paging checks, probes 7 and 18-20 with the same outcomes, `MIRROR_USER_THREADS_OK`, `MIRROR_SCHEDULER_OK` and exact frame restoration, and both wake-precedence rules of readme.md:516/:554. `validate_process` keeps every assertion, now reading outcomes from zombies.
2. Capacity (the new separate check, in role 0 only): one process runs 15 worker threads beside its main thread (16 in total), the 17th create returns EAGAIN, WAKE_U32 with count 16 is accepted and count 17 EINVAL, and the check's single stack reservation is released before sync.rs runs. The pre-existing battery is unchanged (TASKS stays 3), and both roles keep running it.
3. Wait queues (in role 0 only, after its capacity check, so the pair session's peak stays 20): 8 threads wait on one word, launched one at a time with `settle()` (sync.rs:74-80) between them, their stacks in one shared RW reservation (one region, like the capacity check's); one WAKE_U32 (count 16) wakes all 8 in FIFO order, proven by a shared sequence counter; a blocked thread's charged ticks do not move; a 5-tick timeout completes ETIMEDOUT; release and PROT_NONE still cancel with EFAULT (sync.rs's invalidation checks unchanged).
4. Wakeup preemption, placed inside the existing IPC battery so the roles never collide: the deadline half runs in `check_ipc` after role 0's yield (init main.rs:901), while role 1 waits for EOF in RECV_WAIT (init main.rs:927) under its 100-tick deadline (userspace.rs:42) — the check stays far inside that deadline so `timeouts == 0` holds (userspace.rs:862). Role 0's sleeper shares its process with a spinner thread that spins a fixed 4 ticks (well inside the shared 128-tick budget); the sleeper's deadline must be met by the deadline tick's own trap exit, and the spinner resumes with its remaining quantum. The IPC half measures the battery's existing message 1: role 1 sends at init main.rs:918 while role 0 waits in RECV_WAIT at init main.rs:813, so the message counts (userspace.rs:834-847) are unchanged. Both latencies are measured kernel-side (dispatch tick minus deadline; receiver dispatch tick minus the sender's trap-exit tick), recorded only for battery-flagged threads (the fpu_preemption_start pattern, :273-275), and printed as `MIRROR_PREEMPT_OK` — exactly two lines per smoke boot (one per pair session's role 0), each value at most 1 tick (an IRQ delayed across a tick boundary by a critical section).
5. Table bounds: a boot-smoke kernel self-test (the `stacks::self_test` pattern — 0016a's implementation notes; stacks.rs:393) fills the process table to 64 and the thread table to 256, expects EAGAIN, destroys every entry and checks the boot frame baseline is restored exactly; a second case creates a process while the thread table is full and checks the same exact restoration. `heap::capacity_self_test` (heap.rs:587-672) is unaffected: the tables are .bss.
6. Zombie/reap: the fault scenarios leave their Outcome in a zombie until validation; each session drains with its frames restored to its baseline (today's :624/:774-779 pattern, per session).
7. 0019a continuity: with a `mirror.perf=` token, the input-to-present trace (with `burn`) is recorded in QEMU before and after this spec and reported, not gated — the reason the phase measures 0019a first.
8. Before merge (P8): the full `scripts/test.ps1` in debug and release; `test.ps1 -AgentDemo` as well unless open question 1 retires the feature — in the RS6-yes branch, the last `-AgentDemo` run is on the commit before the deletion. The marker and scan-list changes land in the same commit (closed-world rule).
